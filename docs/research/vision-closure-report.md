## 一句话结论

**三处病灶里我们自己那两处已经拆掉，并且量到了数：click accuracy 44.81% → 55.74%（n=183，同一批样本，
官方 bbox 命中口径，**Wilson 95% CI [48.50%, 62.74%]**），越过本轮 47~55% 的目标带上沿；
精定位相对「只用粗定位」的净胜从 +3.28 pp 涨到 **+14.75 pp**（always 102/183 = 55.74%
vs coarse_only 75/183 = 40.98%；配对 mid-p McNemar **p = 9.02e-05**）。**

> **Δ 的方向必须写清楚（产物口径 =「右臂 − 左臂」）**：产物
> `comparison.paired.always_vs_coarse_only` 的 `left = always`（两段式）、`right = coarse_only`（只用粗定位），
> 因此 `delta_pp = -14.754` 表示**粗定位臂低 14.75 pp**；换算成「精定位相对只用粗定位的净胜」就是
> **+14.75 pp**，CI 同一口径为 **[−21.86, −7.65] pp**（`delta_ci95_pp`）。
> 报告里凡出现 Δ，**必须标明是哪一个口径** —— 两种写法数值相同、符号相反。
> ⚠️ 183 条是**分层抽样**（OS 41.5% / CAD 4.9%，与全量 1581 条构成不同；CAD 命中 0/9），
> 按全量构成**重加权后是 42.5%**（CI [35.5%, 49.7%]）→ **55.74% 是抽样构成下的值，不是真值**。

**但两条硬事实吃掉了另外两个目标，且都不是「实现没写对」：**

1. **服务端会再缩图**（探针实测：宽度上限 ≈**2016 px**）→ ⑥ 的 2048 档**探针不过** →
   按施工清单退到 **1536×960**（探针过了）→ **icon 在模型输入图里的中位尺寸只到 12.0 px**
   （n=87，本轮 183 条抽样；全量 604 个 icon 的同口径是 14.00 px）—— **验收线要 ≥16 px，没达成**；
2. **网关忽略 `temperature`**（3 轮 × 10 次连发，**原文一致率三轮都是 10%**）→ ② 的「关采样」目标
   **在本端点拿不到** → 模型方差**没被钉住** → 任何跨运行的分数差都混着模型随机性
   （本轮的头条数之所以敢报，是因为**两臂共用同一次上游回答**，差异里不混随机性）。

**端到端两波没有达标**（wave1 0/5、wave2 3/7），但**卡住的不是视觉落点**：
wave1 的失败全部来自**环境/树**（UWP 树读不到文本、浏览器没登录、浏览器通道没有滚动动作），
而**落点条款这一轮第一次判出来了**：wave1 的 W-3 两次落点都是 **A 命中（到矩形 0.0 px）**，
W-1 的两次视觉定位**明确记了 `undecidable` 并点名缺哪条真值**（树里没有「系统」/「屏幕」的控件框）。

## 三、被证伪的推断

| 推断 | 结论 |
|---|---|
| 「**显式 `temperature=0` 就能关采样**」 | **被证伪**（本机端点）。3 轮 × 10 次连发，**原文一致率三轮都是 10%**（`text_consistency.modal_rate = 0.1`、`distinct = 10/10`），带不带 temperature **没有可测差别**（两个对照轮也都是 0.1）；请求体**确实显式带了** temperature（`src/minicode/model/client.py:208` → `body["temperature"] = temperature`；缺省 `model/config.py:60 DEFAULT_TEMPERATURE = 0.0`）→ **网关忽略 temperature**。⚠️ 落点一致率（`point_consistency.modal_rate`）三轮是 **0.2 / 0.1 / 0.1** —— **与原文一致率不是一个量，不许混着报**。→ ② 的「π_d 降到 ≤10%」**在本端点拿不到**，要靠上游冻结 / 换端点 / 重复采样。证据 `runs/m2-temperature-probe/probe.json`、`probe-no-temperature.json`、`probe-text.json` |

## 四、还剩什么 / 下一步从哪接

### 本轮发现的两个**新风险**（下一轮要先处理）

1. **负出口会制造假否定**：wave1c 的 W-1.2 粗定位答「这张图里没有对应的元素」，

   或者给粗定位的负出口加一层兜底（现在已经有整屏第二遍，但它也照答负出口 → 直接判死）。
2. **精定位没有护栏**：粗定位本来就对的 75 条被弄坏 11 条。

## 五、接口破坏（本轮 · 改名类）

> 公开接口变了 → **下游要改 import**。都在 `src/minicode/eval/`（评测台内部使用；仓库内调用点已同步改完）。

| 改了什么 | 破坏面 | 换成 |
|---|---|---|
| `minicode.eval.holdout`：`HalfResult` → **`FoldResult`**、`evaluate_half()` → **`evaluate_fold()`** | 这两个名字**不再存在**（`from … import HalfResult` 即 `ImportError`；`evaluate_half(...)` 即 `AttributeError`） | `from minicode.eval.holdout import FoldResult, evaluate_fold` |
| `minicode.eval.holdout`：原 `FoldResult`（**一折 = 训练折选阈 + 留出折评**）→ **`FoldOutcome`** | 同名 `FoldResult` 的**含义变了**（现在指「留出折上的**评估结果**」） | `from minicode.eval.holdout import FoldOutcome` |
| `minicode.eval.stats`：`mde(n, discordance, delta)` → **`mde(n, discordance)`** | 第三个位置参数**被移除** → 再传第三个参数抛 `TypeError` | 「这个样本量够不够判出 Δ」由调用点自己比：`Δ ≥ mde(n, π_d)` 即够 |

| 记忆缓存 JSONL 条目 | 多一个 `stage` 字段（旧条目读回记 `unknown`） | 落盘缓存 |

> ⚠️ **为什么把原 `FoldResult` 也改名**：拍板的名字 `FoldResult` **已被占用**
> （那一类装的是「一折的调参 + 评估」）→ 评估结果那类归 `FoldResult`，
> 装「一折」的那类改叫 `FoldOutcome`（与仓里 `ArmOutcome` / `TaskOutcome` 同路子）。
