# 视觉通道根因报告

> **范围**：ScreenSpot-Pro 本地抽样 183 条（三臂）+ 330 条 crop 尺寸扫描 + 42 条重跑 + 6 次标定 + 端到端两波（wave1/wave2）。
> **数据来源**：`runs/g1-eval-330/sspro-report.json`（183 条）、`runs/g1-eval-42b/sspro-report.json`（42 条同配置重跑）、`runs/a2-eval-42/caliber.json`（42 条逐目标误差）、`runs/g1-crop-scan/crop-scan.json`（330 条 × 7 尺寸）、`runs/a1-calib-final/calibration-records.jsonl`（6 次标定）、`runs/d6-wave1|e2e-report.json`、`runs/d6-wave2/e2e-report.json`。
> **诊断线产物**：`.scratch/diag/d1-error-direction/` ~ `.scratch/diag/d8-numbered-in-pure-vision/`（各线模型调用 ≤40 次，全部落盘）。
> **本报告未重跑 183 条全量**；下文每个数字都带样本量，【实测】与【推断】分开标注。任务书里的若干口径与产物不一致处，见文末「附录 B：口径更正」。

## 一句话结论

**视觉通道现在卡在我们自己的三处接线/判据上，不是模型能力上限，也不是环境问题**：整屏缩图（把图标压到模型输入图里中位 13.25~14.5 px）、固定 192 物理像素按粗点裁剪且无 padding（183 条里 66 条 = 36.1% 的 crop 窗口根本没有目标）、偏离回落判据（参考点 = crop 窗口中心、阈值 50 px，43.7% 的落点被自己的判据丢弃）。三者叠加解释了 101 个未命中里的 89 个（88.1%）：66 个属于「窗口里没目标」（接线错），23 个属于「模型答对了、被我们丢掉」（判据错），**只剩 5 个（5.0%）是在目标完整可见时模型指错**。把这三处拆掉，同一批 183 条上可回收 **+2.64 pp（44.81% → 47.45%）**，且 icon 类在原生像素密度下从 35%（7/20）回到 85%（17/20，配对 McNemar 精确检验 p=0.0063）。

## 根因分层

证据强度分级：**强** = 本机对照实验（含配对检验或确定性对照）；**中** = 本机全量日志 / 离线精确重建，无对照实验；**弱** = 单轮观测或外部推断。

| 层级 | 根因类别 | 占 101 个未命中 | 关键判据（样本量） | 证据强度 |
|---|---|---|---|---|
| **L1** | **判据写错**（我们自己丢弃正确答案 + 评测口径把构成差当效应） | 23/101 = **22.8%** | 偏离回落 80/183（43.7%），其中 78 条是 deviation；重放 18 条可救样本，精定位命中 12/18 = 66.7%，同时 12 条受保护样本里精定位也会命中 6/12 = 50% → 净 +4.83 条 = **+2.64 pp**；crop-scan 的 A/B 半差 7/7 同号、均值 −5.63 pp（SE 0.57 pp），独立交叉验证 −6.29 pp | **强**（d4 40 次重放 + d7 离线重建 + 独立交叉验证） |
| **L2** | **协议/接线错**（我们自己做的动作：缩图、裁剪计划、预算、路由） | 66/101 = **65.3%** + 预算 0 pp | 183 条里 66 条 crop 窗口完全不含目标（36.1%）；同粗点把窗口放到 512 → 完整含目标率 42.1% → 71.0%；icon 在模型输入图里中位 13.25~14.5 px，61.4%（216/352）的图标 <16 px；同模型同提示词只改像素密度：35%（7/20）→ 85%（17/20），p=0.0063 | **强**（d5 配对实验；d2 零调用精确重建 183/183） |
| **L3** | **环境/数据问题**（端到端环境可达性、数据集完整性、候选源缺失） | 0/101（不产生 SSPro 未命中） | wave1 的 3 个 fail 全部是执行器/断言问题（`Shell_TrayWnd` 找不到、`ActionResult` 无 `result`、验收期望「判不了」），0 个是「模型指错」；本地 1581 条标注只有 939 张图（缺 648 张）；183 条抽样构成与全量不符（OS 41.5% vs 12.4%、CAD 4.9% vs 16.5%）→ 重加权 44.8% → 42.5% | **中**（本机日志/产物，无对照实验） |
| **L4** | **模型能力上限**（通用 API 模型的 grounding 天花板） | 5/101 = **5.0%**（窗口完整含目标仍指错 5 条）；另 7 条为「目标不完整却被要求指」→ 半归 L2 | 窗内模型那一指命中 41/46 = 89.1%（完整含目标）、20/27 = 74.1%（部分含）、合计 61/73 = 83.6%；窗外 0/30、实测 0/16（n=16 重放）；同提示词同图连发两次 0/4 原文相同、落点差 2.2~129.9 px；跨运行命中翻转率 16.7%~26.2%（6 对运行） | **中**（n=73 / n=16 / 6 对运行；未做公开对照实验） |

### 为什么可以排除「模型能力上限」作为主因（四条互相独立的判据）

1. **换算链精确可逆**【实测，n=1581】：把 GT 框按模型输入空间缩放后喂进我们自己的 `box_center → CoordinateAdapter.to_screen → full_screen_geometry`，1581/1581 条回到 GT 中心，最大误差 4.5e-13 px。→ 不可能有固定偏移或比例误差。
2. **协议 bug 必然是确定性的**【实测，n=4 确定性对照】：逐字相同提示词 + 逐位相同图像连发两次，0/4 次原文相同，落点差 2.2 / 3.6 / 35.5 / 129.9 px。
3. **跨运行命中会翻转**【实测，6 对运行、n=36~42/对】：翻转率 16.7%~26.2%，落点差中位 26.7~68.2 px、p90 1416~1739 px，>100 px 的差占 25.0%~40.5%。→ 落点不是（模型,图,提示词）的稳定函数。
4. **只改像素密度就改变结论**【实测，n=20 配对】：同一模型、同一提示词、同一解析器，原生分辨率 crop 17/20 = 85%，整屏缩图 7/20 = 35%，配对 McNemar 精确 p = 0.0063。

## 逐条现象的解释

### 1. click accuracy 44.8%（82/183）—— **已解释（构成层面），但绝对值偏高**

- **它不是「坐标偏了几个像素」**【实测，n=183】：换算链在 1581/1581 条 GT 上可逆到 4.5e-13 px；找对元素的子集（n=76）落点误差中位 8.9 px、|dx| 中位 8.5、|dy| 中位 2.25、位置回归斜率 x=1.0027 / y=0.9973、命中 92.1%；挑错元素的子集（n=107）误差中位 226 px、|dx| 中位 114、命中 11.2%。两者是两个干净簇，44.8% 的分母里混的是后者，不是系统性偏移。
- **偏移量只占中位误差的一小部分**【实测，n=183】：dx 中位 +1.0 px（符号检验 p=0.824）、dy 中位 −2.0 px（p=0.001，幅度仅 2 px，在模型输入空间只有 0.625 像素）；k = 落点/真值 中位 1.0004，68.9% 落在 [0.9,1.1]；k≈2 仅 1.2%、k≈0.5 仅 1.2%（n=167）。全样本 OLS `dy~gt_y = −0.333`（t=−5.86）是混入 107 条挑错元素后的回归稀释伪影：Theil–Sen = −0.0118、截尾 10% OLS = −0.0071（t=−1.09，不显著）。
- **44.8% 这个绝对值系统性偏高**【实测，n=183 对全量 1581】：183 条抽样先分层后过滤，本地只有 939/1581 张图 → OS 占 76/183 = 41.5%（全量 12.4%）、CAD 占 9/183 = 4.9%（全量 16.5%，且 CAD 命中 0/9）。按全量 group 构成重加权后 **44.8% → 42.5%**。
- **未解释**：78 条回落里 34 条是「目标不在 crop 窗内」的白触发，它们的粗点为什么偏那么远（粗点误差中位 55.9 px、p90 1451 px、14.8% > 1024 px、max 3420 px）——【未解释】，见第 8 节。

### 2. icon 29.9%（26/87）vs text 58.3%（56/96）—— **已解释，差距 28.45 pp 有精确分解**

- **差距分解**【实测，n=183】：icon 29.89% − text 58.33% = 28.45 pp，其中 **16.89 pp（59%）来自「裁剪窗口没框住目标」**（窗口含 GT 中心：icon 45.98%（40/87）vs text 73.96%（71/96）），**11.56 pp（41%）来自「框住之后精定位对 icon 也更偏」**（条件命中：icon 62.50%（25/40）vs text 76.06%（54/71）；不含目标时 icon 2.13%（1/47）vs text 8.00%（2/25））。
- **根因是像素密度，不是模型不会认图标**【实测，n=20 配对】：同模型、同提示词、同解析器，只改送进模型的图像尺度 —— 整屏生产同款 coarse 7/20 = 35.0%（Wilson 18.1~56.7%），GT 中心原生 192×192 crop 生产同款 refine **17/20 = 85.0%**（Wilson 64.0~94.8%）；配对 both=6 / C 独赢 11 / A 独赢 1，McNemar 精确 p = 0.0063；同批 20 条在 183 轮里的免费基线是 5/20 = 25%。
- **为什么整屏级会毁掉 icon**【实测，n=937 可用样本】：`model_input_size_for` 把整屏压到 ≤1280~1920 宽，icon 最大边原图物理中位 28~29 px → 模型输入图里中位 13.25~14.5 px；352 个 icon 目标里 216 个（61.4%）在模型输入图里 <16 px，最小 6.5 px。
- **不是「提示词没说清图标」**【实测】：臂 C 用的就是生产同款 refine 提示词（无描述要求）同样 85%；icon 与 text 的指令画像几乎相同（功能动词 48.0% vs 40.2%，外观词 19.7% vs 13.0%）；粗点从未落在同图另一个标注框里（icon 0/87、text 0/96）→ 不是语义混淆，是「指到空白」。
- **纯视觉下 icon 救不回来**【实测，n=183】：编号候选召回 V0 生产口径 3/87 = 3.4%、V1 单词级 3.4%、V2 全量 OCR 词 5/87 = 5.8%；87 个 icon 里只有 7 个（8.05%）的 GT 区域与任何 OCR 词有像素交集。text 侧同口径 49/96 = 51.0% → 66/96 = 68.75%。
- **未解释（带偏置）**：臂 C 的 85% 含 crop 中心偏置（7 条里 4 条答在中心 5 px 内，离中心中位 2.5 px）→ 85% 应读作上界；无偏的原生分辨率上限未测。

### 3. p90 误差 1300 px（coarse p90 1144~1451 px、landing p90 1191~1434 px）—— **已解释：是「挑错元素」的尾部，不是坐标漂移**

- **尾部是混合物**【实测，n=183 分档】：|dx| 中位 38.5 px（p90 1200）、|dy| 中位 6.5 px（p90 370）→ 横向是主误差轴。分四档：<2 px（n=6，dx=+0.25/dy=0.0）、2~20 px（n=49，+1.0/−1.0）、20~100 px（n=56，−29.5/−2.5）、>100 px（n=72，**+128.5/−10.0**，|dx| 中位 435）→ 符号在档间翻转，不是全局偏置。
- **尾部量级与运行间噪声同源**【实测，6 对运行、n=36~42/对】：跨运行落点差中位 26.7~68.2 px、p90 1416~1739 px、>100 px 占 25.0%~40.5%，最大差 3420 px；其中 `a2-eval-42 ↔ g1-eval-330` 的落点差 p90 = 1416.0 px、最大 3418.9 px，与 183 条的 p90 1451 px 同量级 → p90 就是「模型这次指到了别的东西」的距离，不是我们的换算误差。
- **换算层没有尾巴**【实测，n=1581】：见上文判据 1。
- **未解释**：>100 px 档的 dx 倾向 +128.5 px 在 4 次独立运行里分别是 +128.5 / +173.0 / +18.5 / +225.5（符号检验 p=0.013 / 0.33 / 1.00 / 1.00）→ 现有 72 条样本不足以判定它是真偏置还是抽签。

### 4. 回落 43.7%（80/183，其中 deviation 78）—— **已解释，判据是主因**

- **生产规则不是任务书写的「离粗点 128 px」**【实测，代码 + 落盘】：现行实现是「离 **crop 窗口中心** > **50 px** 即回落」（`ground/gate.py:194` 的 `DEFAULT_DEVIATION_TOLERANCE_PX = 50.0`；128 px 是 `DEFAULT_CONSISTENCY_TOLERANCE_PX`，因「第二次独立粗定位」那次调用已被删除而**永远不可判定**、不参与任何判定）。
- **落盘分布**【实测，n=183】：fallback_cause = deviation 78、call_failed 1、out_of_bounds 1、无回落 103；gate_reasons 几乎全是 `target_tiny`（104/183），`confidence` 与 `consistency` 在 183/183 条上都不可判定。
- **78 条 deviation 里 34 条是白触发**【实测，n=78】：目标根本不在 crop 窗内（判据无意义）；44 条目标在窗内 → 其中 23 条粗点没中（本可救）、21 条粗点已中（受保护）。
- **放宽判据的净收益**【实测，40 次重放、30 个不同样本】：被丢弃的 30 条里精定位命中 18/30 = 60%、粗点命中 12/30 = 40% —— 我们在强制使用更差的那一级。阈值曲线（生产参考点 = crop 中心）：t=50 → 44.55%、t=64 → 46.39%、t=80 → 47.53%、**t=96 → 47.71%（峰）**、t≥112 与 ∞ → 47.45%（平台，极差 0.26 pp）；bootstrap 95%：t=50 [41.94, 46.90]、t=96 [43.26, 51.72]。参考点换成粗定位点：t=64 → 48.48%、t=80 → 48.66%。
- **A/B 迁移检验**【实测，n=330 分半】：A 半上选出的最优 t=96 在 B 半上给 46.11%（= B@∞），比 B@50 的 43.17% 高 2.9 pp → 增益可迁移，不是对 183 条过拟合。
- **未解释**：被丢弃那 78 条的**原始**那一刀的精定位落点不可恢复（未落盘），本线用的是同 crop 的新抽样；命中层面一致（对照 5/5、重问 5/5），但偏离量跨运行可漂 45 px → 阈值附近的逐条归属有噪声。

### 5. 精定位只 +3.3 pp —— **已解释：是净效应，不是无效**

- **它是正负抵消**【实测，n=183 配对，我已独立复算】：both=70、always 独赢=12、coarse 独赢=6、both miss=95 → 净 +6 条 = +3.28 pp；McNemar 精确 **p = 0.238** → 183 条连自己测出来的 3.28 pp 都判不出来；bootstrap 差值 95% CI [−6.56, +13.66] pp。
- **在它该起作用的地方是显著的**【实测，n=107 子集】：只在「粗定位已经偏」的子集上算，精定位救回 12/107 = 11.2%，McNemar 精确 **p = 0.0005**；代价是粗定位已中的 76 条里被弄坏 6 条（6/76 = 7.9%）。
- **为什么净效应这么小**：粗定位本身不可靠（误差中位 55.9 px、p90 1451 px、39.3% > 96 px = crop 半宽），于是精定位被喂了坏窗口 —— 36.1% 的窗口里没有目标，且模型在 crop 里有「复读中心」的倾向（48.3% 的 icon 落点一位不动；臂 C 里 7 条中 4 条答在中心 5 px 内）。
- **未解释**：「精定位弄坏 6 条」里，有多少是模型真的更差、有多少是被 deviation 判据丢掉的正确答案 —— 现有产物没落「若不回落会落在哪」，无法拆分。

### 6. 解析不可用比例 —— **已解释，且不是 44.8% 的原因**

- **全库形态唯一**【实测，全库 5258 条请求】：失败 130 条（2.47%），其中 **no_text 125 条**（占失败 96.15%、占全部请求 2.38%）、超时 2、HTTP 400 ×2、日志行撕裂 1。125 条 no_text 的 `output_tokens` **100% 顶满各自的 max_tokens**（分布 {2000: 103, 4096: 19, 64: 2, 512: 1}），thinking_tokens 等于 max_tokens 或 max_tokens−1 → 形态是「思考链吃光预算 → 只有思考链、没有 text 块」。
- **按预算档**【实测，n=1198 / 3404】：2000 档无文本率 **8.60%**（103/1198）；4096 档 **0.56%**（19/3404）→ 现行 4096 档已经修好。
- **「有文本但解析不出坐标」全库 0 次**【实测，1115 条臂结果】：`fallback_cause = no_output` 出现 0 次，error 文本里含解析失败字样 0 次 → 解析器没有格式问题。
- **对 44.81% 的影响 = 0 pp**【实测，n=183】：183 条那轮（4096 档）5 次无响应 → 3 条样本（`inventor_windows_55` 粗定位空 + 整屏第二遍空；`macos_common_macos_40`、`linux_common_linux_20` 精定位无文本 → 回落粗点）。这 3 条在 on_demand / always / coarse_only 三臂上**全是 miss** → 实测 0 pp，上界 1.64 pp。
- **未解释**：4096 档那 19 条被截断请求的真实思考链有多长（日志在 max_tokens 处就断了）；`output_config.effort` 五档（low/medium/high/xhigh/max）各自的思考 token 上界。

### 7. wave1 0/5 —— **已解释，但与视觉通道无关**

- **实为 6 个工单、自动通过率 0/3**【实测，`runs/d6-wave1/e2e-report.json`】：W-1 fail、W-2 待人工确认、W-3 fail、C-1 跳过、C-2 fail、C-3 跳过（自动通过率 0/3 = 0%，跳过 2，人工代确认 1；去掉人工代确认项后即任务书所说的 0/5）。
- **3 个 fail 的根因没有一个是「模型指错」**【实测，逐条读 reason】：
  - **W-1**：2 步都走了视觉通道且 `ok=True`（定位 26.3 s / 51.1 s），但验收期望「判不了（没有能判它的手段）」、**落点偏差判不了（没有控件中心真值）**、读出的缩放值没读到 → **失败在验收断言，不在落点**。
  - **W-3**：`executor_error: RuntimeError: 找不到任务栏窗口（Shell_TrayWnd）` → 放大步骤根本没产出落点（定位耗时 0 ms）。
  - **C-2**：`executor_error: AttributeError: 'ActionResult' object has no attribute 'result'` → 输入框最终值为空。
  - 跳过 2 个（C-1/C-3）的理由是浏览器通道起的是全新会话、被重定向到登录页。
- **wave2 对照**【实测，`runs/d6-wave2/e2e-report.json`，9 个工单】：3 pass / 7 自动判（另 2 个人工代确认、1 个跳过）。3 个 fail 全在 **browser 结构通道**：E-1、E-2 `target_not_found`（页面结构快照里没有匹配元素）、CC-1 `capability = 'sparse'`；1 个 pass（WX-3）命中的是「模态弹窗 → 零动作下发」停止条件，不是定位能力。
- **未解释（真空）**：真机上视觉通道的落点精度**至今没有任何端到端验收证据** —— wave1 的 W-1 两步视觉定位「成功」但没有真值可比。端到端两波不能用作视觉 grounding 能力的证据。

### 4.1 明确划出的边界（我们改不了的部分）

## 评测设计

### 采用的设计：**配对 + 子集放大 + 精确 McNemar**（d7 的 D2 为主、D3 为辅）

| 设计 | 做法 | 噪声来源 | MDE |
|---|---|---|---|
| **D2 配对变体**（主力） | 同批样本、**复用同一次粗定位回答**、只换被测的那一步（crop 尺寸 / 判据 / 提示词） | 只剩精定位那级：模型重抽地板 d = 0.050（1/20，Wilson 95% [0.0089, 0.2361]）；含 API 故障的保守地板 d = 0.100 | n=183 → 6.5 pp；**330 → 4.84 pp**；937 → 2.87 pp；1581 → 2.21 pp |
| **D3 子集放大**（零成本先行） | 只在「粗定位已经偏」（coarse_only 未命中）的子集上测精定位；子集由**共享的**粗定位回答定义 → 不引入选择偏差 | 子集不一致率 d = 12/107 = 0.112（全部朝一边） | n=183 → 6.94 pp；330 → 5.16 pp；937 → 3.07 pp；1581 → 2.36 pp |
| **D0 现状分半**（作废） | A 半 165 vs B 半 165，两批不相交、模型各自重抽 | 构成噪声 + 重抽噪声 | 165 → 15.34 pp；330 → 10.85 pp；**1581 → 4.96 pp（永远判不出 3 pp）** |

### 为什么必须换设计（现状把构成差当成了效应）
- **构成差 C = −5.63 pp 真实存在**【实测，330 条 × 7 尺寸】：7 个尺寸的 A−B 差 = −5.45 / −4.24 / −5.45 / −8.48 / −6.67 / −4.24 / −4.85 pp（**7/7 同号**），mean = −5.63 pp、sd = 1.51、SE(mean) = **0.57 pp** → 95% CI [−6.75, −4.51]。结构原因：7 个尺寸共用**同一次**粗定位回答（应答记忆端口只发一次），所以 C 是常数、只有精定位那级在独立重抽。
- **独立交叉验证**【实测，n=183】：把 `coarse_only` 臂（只由粗定位决定，与裁剪尺寸无关）按同一次 index%2 划分投影 → A 半 37/96 = 38.5% vs B 半 39/87 = 44.8%，差 **−6.29 pp** → 与 −5.63 pp 独立吻合。
- **层内置换检验 p = 0.97**：183 条量不出构成差，但点估计与 7 尺寸均值吻合。

### 判定阈值与样本量（判 3 pp / 5 pp / 10 pp）
- 配对 d = 0.0984：判 3 pp 需 **n = 858**；判 5 pp 需 309；判 10 pp 需 78。
- 配对 d = 0.100（保守，含 API 故障）：判 3 pp 需 **n = 873**。
- 配对 d = 0.050（乐观，纯模型重抽）：判 3 pp 需 **n = 437**。
- 解析 MDE 已用 40000 次 Monte-Carlo 校验：n=183, d=0.0984, δ=6.5 pp → power 0.778（目标 0.8）。

### 实现清单
1. `src/minicode/eval/__main__.py`：把粗定位的**原始模型回答**（bbox + point，不只是换算后的 `coarse_point`）落进 `sspro-report.json` —— 现在只有 `coarse_point`，推不出 `target_radius_px`，crop 窗口只能近似重建（重建与落盘落点位移中位 1.41 px，183/183 落在窗内）。
2. `src/minicode/eval/sspro.py`：`compare_arms()` 增加 (coarse_hit, always_hit) 的 2×2 计数 + **精确 McNemar** + bootstrap 配对差 CI + 把不一致率 d 落进报告；按 coarse 对/错分层报告。
3. `src/minicode/ground/numbered_bench.py`：删掉 `_run_crop_scan()` 的 `half_a/half_b = index%2`，改成**同一条样本上比较两个 crop 尺寸**（复用同一个粗定位回答 + 同一个 crop 窗口）。
4. `src/minicode/eval/sspro.py`：**API 失败（call_failed / no_output）与模型重抽噪声分开落盘** —— 实测 40 次调用里 1 次 API 故障（2.5%），混进不一致率会把噪声地板从 0.050 抬到 0.100。

### 数据集与成本

## 仍未知的

诊断没能回答、必须靠外部资料或新实验补的：

1. **粗定位的框为什么偏得那么远**：粗点误差中位 55.9 px、p90 1451 px、14.8% > 1024 px、max 3420 px。已排除换算链（103/103 落点落在重建窗口内、坐标契约中位差 4.9 px），但「模型在缩小的整屏上乱框」与「我们对框的解析有系统偏差」之间没有定论 —— 需外部调研（Q8）+ 新实验。
2. **失败组（107 条）的落点是「视觉相邻同类控件」还是随机位置**：数据集每图只有 1 个标注，可用该判据的样本 0 条（无统计效力）；需要人工看图或用 OCR / UIA 候选表交叉验证。这决定「重复采样」是否比「换提示词」划算。
3. **>100 px 档 dx +128.5 px 的倾向**：72 条样本、4 次独立运行分别是 +128.5 / +173.0 / +18.5 / +225.5（符号检验 p=0.013 / 0.33 / 1.00 / 1.00），需 n > 500 才能判定是真空还是抽签。
4. **模型自报 point 与 bbox 中心在更大样本上是否出现差异**：30 条上完全一致（中位误差 20.65 vs 20.65、命中 44.83% vs 44.83%、模型框面积只有 GT 的 1.09 倍），但 30 条里仅 29 条可解析。
5. **原生分辨率下 icon 命中的无偏上限**：臂 C 的 85% 含 crop 中心偏置（7 条中 4 条答在中心 5 px 内），需要在「目标故意偏离 crop 中心」或「crop 中心放诱饵图标」的设置下重测。
6. **整屏级改成原生/分块的总代价**：图像 token、上下文预算、端到端延迟 —— 只测了单次 oracle crop（臂 A 2500~2800 token vs 臂 C 144~341），没测多块发送。
7. **精定位提示词把指令当元素名是否吃亏**（`refine_prompt` 第 3 句「名为「click the maximize button of the window」的元素」）：d3 预算用尽未测，需 n ≥ 100 单独验证；官方 agent 协议是命令式口吻（Qwen computer_use 明确要求「click… with the cursor tip in the center of the element」）。
8. **4096 档那 19 条被截断请求的真实思考链长度**，以及 effort 五档的思考 token 上界 —— 需同批样本在 8192 档重跑（外部调研 Q12 也可能直接给答案）。
9. **纯静态图里 icon 的非文本候选源**：需要检测器级候选（OmniParser 类），本机 6 GB 显存跑不动 → 需外部服务化评估（Q10）。
10. **真机生产路径的视觉两段式行为**：真机走 UIA 候选编号分支（实测 21/21 正确、误差中位 0.0 px / p90 0.5 px），与静态图结论**方向相反**；视觉两段式在真机上的行为未验证。
11. **本地缺失的 648 张图是否系统性缺失**（哪些 app 没下全、缺失样本的难度分布）—— 决定 183 条抽样的偏差能否被外推消除。
