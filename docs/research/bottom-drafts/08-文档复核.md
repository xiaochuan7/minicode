| **② 浏览器网页内容**（Edge / Chrome 的页面 DOM） | ⚠️ **树存在，但结构扁平** | Chromium 通过 **MSAA / IAccessible2 → UIA 桥接**暴露元素：能枚举出（**这正是 czdcode 实测 Edge 拿到 126 个候选的原因**），但 AutomationId 多为浏览器生成的动态串、role 泛化、部分元素 BoundingRectangle 缺失 → **"候选数多" ≠ "可用于精确 grounding"** |
| **③ Electron 应用** | ❌ **默认不可用** | Electron 渲染进程**默认不暴露无障碍树**（`app.enableAccessibility` 默认 false），需 app 端开启或加 `--force-renderer-accessibility`；很多 Electron 应用从未开启 → 树可能**完全为空** |
| **④ Canvas / WebGL / GPU 自绘 / 游戏** | ❌ 完全没有 | 像素画上去的，没有任何语义节点 |

### 裁决

- **win-stack-expert 的"UIA 在 Electron/Chromium 失效"**：对 **③ Electron 应用（默认配置）**和 **④ 自绘**成立；把 **② 浏览器网页内容**一并划进去则不成立。
- **project-scout 的"Edge 拿到 126 个候选"**：对 **②**成立，且**恰恰证明"数候选数"这个判据在浏览器上会误判为"可用"**。

### 建议的正确表述（可直接替换 §2 L1 那行）

> **失效与否取决于宿主形态，不是渲染引擎：**
> ① 原生 Win32/WinForms/WPF/UWP → UIA 完整可用；
> ② **浏览器网页内容（Edge/Chrome）→ 树存在但结构扁平**（Chromium 经 MSAA/IAccessible2 桥接到 UIA，元素能枚举，但 AutomationId 动态、role 泛化、部分元素缺 BoundingRectangle）→ **候选数多不等于可精确 grounding**；
> ③ **Electron 应用 → 默认不暴露无障碍树**（需 app 端 `app.enableAccessibility=true` 或 `--force-renderer-accessibility`）→ 按"空树"处理；
> ④ Canvas/WebGL/游戏自绘 → 完全无。
>
> **判定可用的正确姿势不变：递归子窗口 + 看 UIA ClassName，不数候选数。** Edge 的 126 个候选说明的正是"数候选"这个判据在浏览器上会误判——浏览器属于"树存在但不可直接 grounding"，应落到视觉兜底，而不是"UIA 可用"。

**同时建议在 §8 风险清单里把"Electron/自绘 app 的 UIA 失效"拆成两行**：
- "Electron 应用 UIA 树为空 → 定位回落到视觉"（**可探测**：树为空是明确信号）
- "浏览器网页内容 UIA 结构扁平 → 元素可枚举但不可靠 grounding → 按不可用处理"（**不可探测**：树非空但质量差）

## 九、给 lead 的三点总体判断

1. **这份文档的骨架是对的。** §0 的 3 条结论（坐标不是瓶颈 / 结构优先 / harness 优先）与附录 B③（Anthropic 14% 漂移）、附录 B①（Tars 归属）、附录 B②（UI-TARS-2 无权重）**都经得起一手源核验**，我逐字命中了官方原文。第 6 节 D.5 的 Windows 坑位清单也与我独立调研一致。

2. **真正的风险不在结论，在"抄进去的常数"。** 本文最可能咬人的三处都是**系数/量纲**而不是观点：① gui-plus 用 32×32×1280 而非 28×28×1280（176 px 误差）；② OpenAI GA 已无 display 尺寸；③ UI-TARS 到底绝对像素还是 0~1000（文档内部两处打架）。这三条都属于**静默错位**类 bug——和文档自己在 §8 列的第一条风险（"模型/服务商的坐标标度变更 → 静默错位"）同型，只是成因是**写代码时抄错了参考系**，不是服务商改了行为。**§1.4 的运行时标定探针能挡住其中任何一条——建议把 §1.4 的地位从"可选加固"提到"必做"**，并把探针的目标点扩到屏幕最右边缘。

3. **MiniMax 这一节要改的是"证据等级"，不是"选型结论"。** 价格、1M、多模态、effort 五档、thinking 不可关闭（且**默认 max**）——**全部属实**，官方文档逐字可查，§4.4 的"大脑用 M3.1 Flash、定位交给 UIA/crop"的分工也站得住。要改的是三处**措辞**：
   - **61.7 是 partial score，且无独立榜单条目**（我重拉官方榜逐行确认：榜上只有上一代 `MiniMax M3` 的 75.19%）；
   - **"2026-10-23 开源"在官方渠道无出处**（官方只说 "later"；HF 至今无条目）；
   - **对比表的 70.6/65.7/54.3/58.3 来自博客图表而非正文，口径未标注**——只要其中任一其实是 binary，"国产第一"就不成立。
   另外，文档漏掉了一个**对 MiniMax 有利**的事实：**M3（开源权重）在 OSWorld 官方榜有 75.19% 的独立复现**，比 M3.1 Flash 的自报 61.7 更可核验——如果要给这个系列找外部背书，要找的是 M3，不是 M3.1 Flash。
