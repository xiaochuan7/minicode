## 三、哪些推断被证伪 / 被改写

| 推断 | 结论 |
|---|---|
| **「无条件 crop 整体 −0.3 pp」**（本仓文档里流传的那个数） | **正式作废**：多轮调研都找不到一手出处，**本机同批实测的结论相反**（门控开 38.1% vs 门控关 57.1%）→ **一律不引用** |
| **「上一轮那 57.1% 是我们该守住的基线」** | **不成立（口径问题，不是回归）**：57.1% 是 **42 条**上的数（Wilson 区间约 **±15 pp**，方案自己的验收表就写着「42 条分不开 38.1% 与 57.1%」）；同批新代码是 **42.9%** → **两个数分不开**，既不能宣称提升、也不能宣称回归。**可信的数字是 ≥300 条那一批**（见下）与 **M8 基线 14.3%（同批）→ 42.9%（+28.6 pp）** |
| **论文 Table 5「1024² 最好」** | **在我们这台机器上不成立**：330 条实测 1024 → **43.9%**、1280 → **42.4%**，都比 512（46.7%）差 → **两组证据冲突，实测赢了**（冲突的原因见下条） |
| **「误差 ∝ 模型视图宽 → 调小」**（本仓自己的旧实测） | **也不成立**：128 → 37.9%（比 512 差）→ **最优在中间**（192~512 彼此差 ≤1 条样本 = 噪声） |
| **「门控的触发条件是精定位的前提条件」** | **证伪**：门控的触发条件（「两次独立粗定位不一致」）**恰好是精定位前提条件的反面** —— 分组复算：判 `coarse_inconsistent` 的 10 条两臂落点**逐条相同**（+0.0 pp），其余 32 条门控关掉精定位反而 **+25.0 pp** |
| **「门控是省模型调用的信号」**（M23 的旧结论） | **本批也不成立**：门控开 **2.381** 次/目标 vs 门控关 **2.000** → 「再问一次模型算一致性」比省下的精定位**更贵** |
| **「zoom-consistency 路由能省调用」** | **公开同构实现本身就是 null result**（+0.8%，McNemar p=0.19）→ 我们把那一次调用**删了**，只保留**事后**的几何量（偏离量 + zoom consistency）落盘 |
| **「通用 API 模型认不出图标」** | **证伪**（就我们的规模而言）：门控关那一臂 icon 40% / text 72.7%，**高于公开的通用 API 基线**（GPT-4o 0.8% / Claude 3.7 27.7%）；**图标召不回的成因是候选源**（OCR 原理上召不回没有文字的图标），不是模型 → UIA 主表一接，真机 **21/21** |
| **「crop 越大越好」与「crop 越小越好」** | **两个方向都不对**（见上表）→ 尺寸必须**自己扫**，不能照抄任一边 |

## 四、还剩什么

1. **落点长尾 p90 ≈ 1300 px 没解决**（中位只有 ~53 px）—— **模型在 crop 里选到完全不同的元素**是主因；公开可抄的路子是 **GUI-RC 的空间投票**（K 次采样 + 点扩成方块 + 取最大连通块）或 **LFPR 的几何护栏**（中点融合）—— **本轮没做**。
2. **精定位产出率 39%~82%（随尺寸）**，没到 90% —— 回落判据的**参考点改成 crop 窗口中心**之后，窗口越大被 shift 掉的越多 → **这条曲线混着「尺寸」与「判据参考点」两个效应**，要分开需再跑一臂（参考点做成运行时参数）。
3. **crop 扫描没留逐样本记录**（只有汇总）→ 看不到**回落原因**的分布（偏离 / 无输出 / 越界）。
4. **wave1 仍 0/5**：缩放值已读到（W-1.E ✓），但两条期望仍「判不了」（UWP 树里观察不到文本）+ W-1.C 落点偏差**没有真值**（树里没有「系统/屏幕」的控件框）→ **读值层已修，断言层/真值层要另开**。
5. **wave2 的 E-1.1 / E-2.1 覆盖失败** → 候选源问题（混合候选源已接**生产**，但那两张票走的是 `ElectronExecutor` 的页面结构快照路径，**本轮没接到那条路上**）。
6. **CC-1.A** 要 `capability == "usable"`，本机 cc-switch 的树现在「同名撞车 6 处」→ **这条 AC 在本机不成立**，待拍板（改措辞，还是让应用侧改名）。
7. **W-3 的验收条款措辞过时**：`e2e/wave1.py` 的 `LANDING_TOLERANCE_PX = 2.0` 是 **UIA 那条线**，而 W-3 走的是放大（视觉）路径，现在离时钟中心 15.0 px、对包围盒中心 1.1 px → **真值口径要定**（「目标中心」指哪个中心）。
8. **P1 的其余块**（B-2 出框已由改动 4 顺带做掉一半；B-3 自洽度、C-1/C-2 迭代 zoom、C-3 zoom-consistency、D-3 上下文裁剪、D-5 窗口标题）**本轮没做**。
9. **P1 的门控两条**：`undecidable` 现在只剩 `confidence` / `consistency` 两条不可判定 → 要 B-3（自洽度）才判得了。
