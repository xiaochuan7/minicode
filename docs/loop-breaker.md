# Loop Breaker（W7 主线 C1）：重复计数器自愈层的设计、口径与实测

> 组件：`src/minicode/reflection/loop_breaker.py`（测试 15 用例全绿）；
> 接线：`scripts/w4_long_tasks.py`（每步 observe + 计数器无条件落盘）。
> 参考：VLAA-GUI（arXiv 2604.21375）的 Loop Breaker 机制。

## 一、为什么不是又一个结果分类器（本节最重要的一句）

既有自愈层（`HealedStepExecutor`）是**结果分类器**——`not_clickable` 是对
前置条件的判定，只在「刚好复现那个失败形态」时才响，T1–T4 整夜只响 2 次。
Loop Breaker 是**重复计数器**：每步无条件记录、无条件计算，窗口被填满
就一定触发。这是两种东西：分类器的漏报是「形态没复现」，计数器的漏报
只能是「窗口没填满」。

## 二、三层设计（阈值 = 论文口径，常量钉死）

| 层 | 计数器 | 窗口/阈值 | 触发后果 |
|---|---|---|---|
| 1 | 动作重复 `n_a_t = |{i∈[t-1,t]: a_i=a_t ∧ o_{i+1}≈o_i}|` | 窗口 2 / τa=2 | 切换**交互方式**（键盘快捷键 → 菜单点击 → 命令行） |
| 2 | 观测重复 `n_o_t = |{i∈[t-2,t]: o_i≈o_t}|` | 窗口 3 / τo=3 | 更换**整体策略**（菜单导航 → 直接改文件） |
| 3 | 模型裁决 | 前 2 层未触发 + stall 连续 ≥6 步（**自定**，论文未给层 3 触发式） | 一次模型调用 keep/switch；switch 下发**只作用于下一步**的黑名单（非永久封禁） |

窗口大小恰等于阈值 → 触发条件就是**窗口被填满**。阈值不许放宽（工单纪律）。

## 三、``≈`` 的度量（**自定**，论文未定义）

* 缺省 `DigestComparator`：观测指纹（UIA 前几个控件值拼接）**精确相等**。
  理由：确定性、零依赖、可复算。代价：对真机噪声更敏感 → 更难判「≈」
  → 倾向**少触发**（fail-closed 取向）。
* 真机可换 `PhashComparator`（感知哈希汉明距 ≤ 8/64，自定阈值）。
* 实现口径注记：`n_o` 的窗口取「最近 3 个观测」，比论文的 [t-2,t] 索引
  平移 1 位（判定时机在动作执行完之后），语义相同；测试已钉死。

## 四、三条纪律（照论文）

1. **loop-break ≠ fail**：重复本身不构成任务不可行的证据；触发只产出
   「换方式」指令，从不判任务失败（测试断言 verdict 结构里没有 fail 语义）。
2. **两个计数器每步无条件落盘**（`runs/w4-long/loop-counters.jsonl`，带
   task/step 字段）—— 结果分类器时代只在 heal 时留痕，导致分不清
   「触发太窄」和「策略无效」；无条件落盘正是为了拿到计数器的**取值分布**。
3. 阈值是常量（`LoopThresholds`，测试对照论文值）。

## 五、成本与预算的诚实口径（**买步数，不买成功率**）

* 加它会让动作数上升：论文 60 任务子集，完整版 19.67 动作 / 47.39 次
  模型调用；只留判定器的版本 27.32 动作 / 89.13 次调用。
* **强模型上它几乎不加分甚至微负**：Sonnet 4.6 @100 步，去掉它
  71.67 → 71.63（−0.04）。
* **强烈依赖步数预算**：Gemini 3 Flash，15 步预算 −6.15pp，50 步 +4.24pp，
  100 步 +1.82pp。
* **结论**：Loop Breaker 是长任务专用件，买的是「步数」不是「成功率」。
  本仓不做成功率卖点（README 与本节同口径）；它在 T5–T10 那种
  30+ 步任务里才有意义。

## 六、接线与「三个数」

* `w4_long_tasks.py` 每步执行前后取界面指纹 → `observe(step, action_key,
  obs_before, obs_after)`；每条记录落 `loop-counters.jsonl`；触发时黑名单
  随下一步的步骤记录下发并打印。**骨架接线如实声明**：黑名单当前随步骤
  记录下发（可见、可审计），**改变执行行为的注入点**（决策层消费黑名单）
  留作下一步 —— 本夜不动决策层。
* 三个分开的数（进 attempt 结果的 `loop` 字段）：
  `encountered`（重复发生步数）/ `triggered`（触发自愈次数）/
  `recovered`（触发后 1 步内观测出现可见变化的自定义口径）。
* **强制触发测试**（合成场景，与「现实里多久触发一次」解耦）：
  构造同键动作 × 2 + 观测无变化 → 层 1 必触发；最近 3 观测 ≈ → 层 2 必触发；
  注入 gate + "switch" 裁决 → 层 3 必触发、黑名单只作用一步（取后即清）。
  15 用例见 `src/minicode/reflection/test_loop_breaker.py`。

## 七、计数器取值分布（T1–T4 现状）

T1–T4 接线**之后**尚未重跑（本夜时间预算）；接线**之前**的 4 条 attempt
没有计数器分布数据（如实：这正是 §4-2 无条件落盘要解决的问题 —— 下一批
跑完，`loop-counters.jsonl` 就有每步的双计数器分布，触发率、stall 长度、
层 3 的真实调用次数都从那里算，不再靠推测）。
