# W2 精定位专项量化报告：两级链路的第二级有没有独立价值

> 2026-11-04 定稿。四份数据（原始 JSON 全部入库，可复算）：
> [docs/refine-quant.json](refine-quant.json)（S-Pro 三臂）、
> [docs/canvas-refine.json](canvas-refine.json)（canvas 偏移扫描）、
> [docs/crop-size-offline.json](crop-size-offline.json)（离线 crop 几何）、
> [docs/retry-effect.json](retry-effect.json)（重试效果）。
> 模型 deepseek-v4.1-flash @ opencode（与 W6/V2 同款）；判定 = 官方 bbox 包含。

## 0. 一句话结论

**精定位一级有独立、可统计显著的价值**：同批配对下，粗定位单独 13/46（28.3%）
→ 粗+精 22/46（47.8%，Δ=+19.6pp，mid-p McNemar p=0.006，CI 排 0）；给准粗点
（GT 中心）时粗+精到 73.3%（Δ=+51.7pp 达 MDE）。中位误差 41px → 5.7px。
zoom 的生产规则有正贡献（+8.3pp）。生产参数（crop 1×、取整、zoom 触发）全部
**维持原状**——每一项的 A/B 数字都不支持改动。

## 1. W2.1 S-Pro 同批 60 条，注入式三臂（配对口径）

**方法**：注入式粗定位客户端（`CoarseInjectingClient`）替换第一级应答，
第二级**全生产代码**（真裁剪/真放大/真问模型/真换算，复用 `TwoStageGrounder`
与 `eval/sspro.py::_run_one`，不复制管线）。基线 = W6 pixel 臂（粗定位单独，
同批同提示词同判定，零新调用复用）。

| 臂 | 粗点 | zoom | n | 命中 | 中位误差 | p90 误差 |
|---|---|---|---|---|---|---|
| 基线（粗定位单独） | 模型真实 | — | 46 配对 | 13（28.3%） | 41.0px | 373px |
| `real_nz` | W6 真实落点 | 无（零面积框） | 46 | **22（47.8%）** | 17.8px | 245.8px |
| `gt_nz` | GT 中心 | 无 | 60 | **39（65.0%）** | 9.1px | 48.1px |
| `gt_zoom` | GT 中心 | 生产规则 | 60 | **44（73.3%）** | 5.7px | 42.5px |

⚠️ 诚实口径：W6 未存模型自报框 → `real_nz` 用零面积框（生产里真框会触发
zoom）→ real 臂是**下界口径**；zoom 的影响由 `gt_zoom vs gt_nz` 单独量。
`real_nz` 跳过 14 条（W6 无粗点的样本，精定位无处安窗）。

**配对统计（mid-p McNemar 主报 + 配对 bootstrap 95% CI）**：

| 对比（同批配对） | Δ | 95% CI | p | 达 MDE？ |
|---|---|---|---|---|
| real_nz vs 基线（n=46） | **+19.6pp** | [+6.5, +32.6]（排 0） | **0.0063** | 否（MDE 20.2） |
| gt_nz vs 基线（n=60） | **+43.3pp** | [+28.3, +58.3]（排 0） | **1.4e-6** | **是** |
| gt_zoom vs 基线（n=60） | **+51.7pp** | [+38.3, +65.0]（排 0） | **4.1e-9** | **是** |

逐样本误差配对（46 条可比样本）：real_nz 让 **32 条变好、8 条变差**；
基线唯一命中而臂未命中的只有 1 条（翻转方向几乎单向）。

**回落**：三臂各 14 条回落粗点（12 条 `call_failed` + 2 条 `no_output`，同一批
难样本）——占 166 次臂调用的 23%~30%。

**粗点质量的影响**（同「不放大」口径直接比）：gt_nz 65.0% vs real_nz 47.8%
（17.2pp）——精定位能救回相当一部分粗点误差，但救不回全部：粗点错得离谱时
crop 窗本身就罩不住目标。

## 2. W2.2 自建 canvas 页，粗点偏移扫描（真值可控）

22 目标三档密度（小图标 ≤16px ×8 / 中等按钮 ×8 / 密集清单行 ×6），GT 从截图
实测（品红测量条，DPR≈1.49 一致性校验）。每目标 × 偏移 {0, 50, 100, 200}px
（方向轮转 8 方位），88 次定位全部产出落点（**零回落**）。

| 密度档 | offset 0 | offset 50 | offset 100 | offset 200 | 救回（strict / pad8 / 误差缩小） |
|---|---|---|---|---|---|
| 小图标（≤16px） | 7/8（中位 5.9px） | 7/8 | 6/8 | **3/8** | 16/24 / 20/24 / 21/24 |
| 中等按钮 | 8/8（中位 6.4px） | 8/8 | 8/8 | **7/8** | 19/20 / 19/20 / 20/20 |
| 密集清单行 | 4/6（中位 5.7px） | 4/6 | 6/6 | 5/6 | 10/12 / 10/12 / 12/12 |

**读法**：

* **粗点给准时**，精定位中位误差 5.7~6.4px（≈半格图标）——第二级确实把
  落点收敛到目标上了；
* **50/100px 的粗点漂移基本无感**（按钮档 8/8 全保）；
* **200px 是小图标的能力边界**（3/8 strict、5/8 pad8）——窗口偏太远时
  16px 目标不在 crop 里或被放大失真；
* 密集清单在 offset 0 就有 2 例找错行（26px 行距的固有难点，与粗点无关）。

## 3. W2.3 有据优化（每项 A/B 数字；结论全部 = 维持原状）

### 3.1 crop 尺寸比例（离线几何，n=46 有真实粗点）

| 档位 | GT 含住率 |
|---|---|
| 0.5×（= 0.25×帧） | 86.96% |
| **1×（= 生产现状 0.5×帧，下限 512）** | **95.65%** |
| 2×（= 整帧封顶） | 100% |

减半丢 8.7pp 含住；翻倍只赚 4.3pp 且摊薄放大倍率 → **维持 1×**。

### 3.2 zoom 触发条件（W2.1 内建 A/B：gt_zoom vs gt_nz，同 GT 粗点）

73.3% vs 65.0%（**+8.3pp**），中位误差 9.1px → 5.7px → **生产 zoom 规则保留**。
小图标档在 canvas 上 offset≤100 时 7/8~6/8 strict 也受益于放大（目标表观像素
≥30px 的规则在小目标上正是主杠杆）。

### 3.3 crop 原点取整

`plan_crop` 以 `int(round(...))` 取整，无半像素来源；canvas offset=0 的实测
中位误差 5.7~6.4px 中无系统性 1px 偏移迹象（GT 本身 ±1px、目标绘制 ±1px、
DPR 取整的贡献都在这一量级）→ **无改善空间，维持原状**。

### 3.4 精定位失败重试（W2.1 请求日志反推，155 次调用序列）

attempt1 成功 45.2% → **加重试 83.9%（+38.7pp）**；16.1% 三次耗尽回落粗点。
⚠️ 口径注记：3 worker 并发下按日志顺序切分序列是**估计值**（失败行会跨调用
交错）；权威的回落率以上表 outcomes 为准（23%~30%）。
**结论：重试是精定位可用性的关键一半**——没有重试，今晚的 S-Pro 命中率会
从 47.8%/73.3% 掉到接近粗定位基线。

## 4. 对生产的建议

1. **两级链路保留**——精定位一级在配对口径下统计显著（p=0.006 ~ 4e-9）；
2. 生产参数全部维持：crop 1×、`int(round)` 取整、表观像素 ≥30px 的 zoom 规则；
3. 真正的瓶颈不在精定位几何，而在**模型输出的稳定性**（思考链吃穿 token
   预算 → 23%~30% 回落）——这是模型/网关侧问题，不是几何参数问题；
4. 小图标 + 200px 级粗点误差是能力边界，靠粗定位质量而非精定位参数解决。
