## 2. 方案 B 的组成（拼装 + 自建两个缺口）

**一句话**：不重写、也不直接用别人的成品，而是**拼装成熟骨架 + 只补两件别人没有的东西**。
依据：2026 年的胜负手在 harness 而不在 checkpoint（OpenGCUA 同一批 8 个模型只换 harness，OSWorld-v2 平均部分分 **45.3→64.9**，步数 **−53%**）。

### 复用（不自己写）

| 角色 | 选型 | 说明 |
|---|---|---|
| **骨架** | `microsoft/UFO`（MIT，Windows 原生） | UIA + Win32/WinCOM/MCP 混合动作空间；坐标系天然就是 UIA 物理像素 |
| **UIA 通道** | `Windows-MCP` / `sbroenne/mcp-windows` / 微软 `winapp CLI` | ⚠️ 接入前必须按架构备忘 §1.5 自查坐标空间（Windows-MCP 有过物理/逻辑坐标混用的 bug） |
| **浏览器那一半** | `microsoft/playwright-mcp` | 走 DOM/CDP，不碰像素 |
| **大脑** | **MiniMax M3.1 Flash**（`minimax-m3.1-flash-free`） | ✅ **可编程 API 已实测可用**（zen 通道 HTTP 200，见 `docs/01-现状.md`）；原生多模态、1M 上下文 |

### 自建（两个缺口，别的地方没有）

1. **两级 grounding 的 crop 精定位回路** —— 全行业只有 Anthropic 把 zoom 做进了官方协议。
   - 现成可抄：`ScreenSpot-Pro-GUI-Grounding` 自带 5 个 coarse-to-fine 实现，形状与本方案完全一致（整屏 → 粗 bbox 中心裁 → crop 内第 2 遍 → 映射回全图）。
   - 本仓库已有：**`src/minicode/coord/crop_refine.py`**（crop 内坐标 + 原点偏移契约）。
   - ⚠️ 必须**按需触发**（无条件做 crop 实测反而更差：ScreenSpot 上整体 −0.3pp）。
2. **校验 / 反思层** —— expect 断言、无变化检测、循环熔断、**三段耗时埋点**。

## 3. 坐标契约（三层，**不许混用**）

```
模型空间          相对空间          截图像素            物理表面空间 ★唯一真值
0~1000 归一化  →  [0,1]×[0,1]  →  截图的像素    →  物理像素 + 虚拟桌面原点
（量纲由运行时标定决定，代码里不写死）
```

| 规则 | 内容 |
|---|---|
| **唯一真值** | **物理像素 × 虚拟桌面原点**。模型坐标永远留在 frame 内（正数），负坐标只存在于执行层 |
| **模型端量纲** | 实测为 **0~1000 归一化**（`docs/01-现状.md` §3.1），但**分母不得写死在代码里** —— 由运行时标定探针决定 |
| **工程端** | 全程物理像素。DPI 感知之后**整套换算里不需要出现缩放系数**；`capture_to_physical_scale` 默认 1.0，非 1.0 必须打警告 |
| **crop 契约** | **crop 内坐标 + 原点偏移**（本方案）。⚠️ 不是 Anthropic 那套"模型在放大图里仍报整屏坐标" —— M3.1 Flash 没被训过那套，混用必错 |
| **落点产生位置** | 整屏归一化坐标只用来"选哪块区域"，**永远不直接点击**；**视觉通道内**最终落点只在 crop 尺度上产生，**UIA 通道的落点直接取控件框的物理像素中心**（不经过 crop） |
| **换算实现** | `src/minicode/coord/coordinates.py`（`CoordinateAdapter`）与 `crop_refine.py`（`CropRefiner`），50 个单测全绿 |

## 4. 三条红线（架构备忘 §2.5「三条跨层硬规则」）

> 这三条是**硬规则**，不是注意事项。实现时最容易做错的就是它们。

**① L1（UIA）→ L2（视觉）的切换只认「coverage failure」，不认「任何错误」。**
> coverage failure = UIA **产不出任何候选**（无 provider / 树被门控 / 目标不在树里）。
> 候选不唯一（先做**消歧**：在 UIA 候选集内让模型只做指认，候选唯一时零模型调用）、被遮挡、尺寸异常、树读取超时、名称匹配不上 —— 这些**禁止切视觉**，必须走 L4 的错误处理。
> 理由：把"切视觉"当通用兜底，会让每步都付 1.5~5 秒，架构优势全丢。

**② 换算链路必须单一来源。**
> 缩放系数、标度、crop 偏移都只能有**一个**真值来源。旧项目在文档里写 `physicalX = pixelX / dpiScale`、
> 代码里故意不换算、靠注释兜住 —— 这类分叉会让文档与代码各说各话。§1.3 的换算式与 §1.4 的标定值
> 必须是**同一个对象的两个方法**。

**③ 三段耗时 + 三类失败必须拆开埋点。**
> 三段耗时：定位（UIA 查 / 视觉推理）｜决策（模型）｜执行+校验（动作+截图+断言）。
> 三类失败：定位失败 ｜决策失败 ｜执行失败。每步日志必须同时记这三项。
> 理由：旧项目缺这个埋点，"调了半年不知道该改哪一层"。

> 📌 架构备忘后续**追加了第 4 条**（§2.5 ④）：**crop 精定位必须按需触发，不能每步必做**。
> 它与 ① 同源 —— 两者都在说"**兜底要罕见**"。

## 6.2 M1 模型客户端（2026-10-20 新增）

业务代码落在 **`src/minicode/model/`**（新目录，纯标准库，不动三个冻结原型）：

| 模块 | 作用 |
|---|---|
| `config.py` | **凭据的唯一来源**：仓库 `.env` 的六项（端点/密钥/模型/会话标识/两个必需头）；缺项或为空 → 显式报错点名；免费档通道（`/go` 后缀）是**可测的规则** |
| `effort.py` | 思考档位五档枚举 `low/medium/high/xhigh/max`（缺省即最高，所以**省略即报错**） |
| `client.py` | 模型客户端：请求构造（纯函数）+ 响应解析；模型侧错误如实回传；**HTTP 200 但没有文本输出 → 显式失败**；坐标**原样透传**（不乘分母、不猜量纲） |
| `request_log.py` | 请求日志：每条请求一条（档位/模型/端点/HTTP 状态/耗时/输入输出 token/思考 token），JSONL 落盘 |
| `fakes.py` | 假模型响应，含「**思考吃光预算导致无输出**」的失败形态（供单测在动作执行缝上用） |
| `regressions.py` | **四个坑的真调 API 集成回归**（单独入口：`python -m minicode.model.regressions`；不被单测命令带跑） |

**实测结论（2026-10-20，与工单假设有出入，详见 `docs/01-现状.md` §2）**：
坑① 去掉 `user-agent` → **HTTP 403**（响应体是 Cloudflare `Error 1010`，「1010」是错误编号不是状态码）；
去掉 `x-opencode-client` → **HTTP 200，服务端已不再强制这个头**（此前「两个头都必须」从未被单独测过）。
坑②③④ 三条与工单一致（FreeTierError / HTTP 400 invalid_request_error / 思考链吃光预算 → 没有文本输出）。

## 6.3 M2 控件树脱敏器（2026-10-20 新增）

业务代码落在 **`src/minicode/redact/`**（新目录，纯标准库，不动三个冻结原型）：

| 模块 | 作用 |
|---|---|
| `patterns.py` | **五类敏感模式**（密钥前缀形态 / JWT 三段 / 长 base64 / ≥32 位十六进制串 / 私钥头）与两个**固定占位符**（密码 `***`、敏感片段 `[REDACTED]`） |
| `config.py` | 模型上下文的两个开关（送树进模型上下文 / 脱敏已启用）+ **启用期校验**（前者开、后者关 → 配置层报错）+ 从**仓库 `.env`** 装载（两个可选键，缺省都是关） |
| `redactor.py` | 把树变成**模型侧文本的唯一出口**：字段白名单 + 正则脱敏 + 密码框占位符 + **硬闸门**（脱敏没上线 → 拒绝，一个字符都不产生） |
| `report.py` | **脱敏计数**：密码框替换数 / 正则命中数 / 丢弃正文类字段数 / 输出长度（+ 一个 fail-closed 的丢弃字段计数） |

缝内接线（`src/minicode/action/`）：动作执行缝多一个 `model_context_config` 注入点
（**不是回调**——缝自己持有脱敏器 → 模型侧文本没有第二个出口）；
**缺省 = 这条通道不把控件树送模型**（零模型调用的通道不受影响）。
追踪记录里带一份**已脱敏**的模型侧视图与脱敏计数；追踪记录里的**值**不落（密码框留占位符）。

**四条与工单假设不同的现实（2026-10-20）**：

1. **冻结原型的 UIA 元素不暴露敏感属性**：`exec/uia.py` 的 `Element` 只给
   `name` / `automation_id` / `class_name` / `rect` / `control_type` 等，
   **没有 `Value` / `IsPassword` / `HelpText`** —— 真机接线（UIA 通道，M3）
   必须自己读 COM 属性，否则密码框规则在真机上永远不触发。
2. **控件名与控件框在追踪记录里保持原值**：脱敏只改「要外发的表示」。
   值不落追踪记录（密码框留占位符，其余为空），连 `repr` 都不带值；
   **控件名里的密钥明文仍会进日志**（落盘前的日志清洗是 M17 的活）。
3. **正文类控件的判定用类型子串**（`edit` / `document` / `text`），
   不是枚举查表——真机上的类型名带厂商后缀（`RichEdit`、`Document2`）时也能命中。
4. **工单的「配置层」此前没有对应的仓库配置项**：仓库唯一配置源是
   `model/config.py` 装载的 `.env`；本轮补了两个**可选**键
   （`MINICODE_SEND_TREE_TO_MODEL` / `MINICODE_REDACTION_ENABLED`），缺省都是关（fail-closed）。
