## What to build

一条命令跑完最小闭环：进程先做 DPI 感知自检（不通过直接中止，不进动作层）→ 抓一帧物理像素整屏 → 从控件树唯一定位一个已知按钮 → 落到物理表面空间的一个点 → 按「移动 → 停 60ms → 按下 → 停 40ms → 抬起」注入一次真实点击 → 回读光标 → 写出恰好一条动作记录。

用户看到的结果：这次点击落在按钮中心 2 个物理像素以内，回读与落点一致且不是哨兵值；全程零模型调用、零费用、不需要任何凭据。同一套接线在动作执行缝上（目标描述 + 一帧截图 + 可选控件树快照 → 动作 + 最终落点 + 意图）用假实现可观测：不打真桌面、不产生费用。

本单同时立住动作协议 v1 的形状（版本号 / 动作种类 / 参数 / 结果 / 错误码）、越界判定（2 px 越界容差，报错不夹取）、截图只落哈希不落原图、每步一条动作记录（含三段耗时与三类失败字段）。后续工单按协议 v1 扩展，不各写一套。

验收目标按钮由运行参数指定（默认取名称稳定、副作用可逆的已知按钮）：执行层自检命中的任务栏控件名会随天气变（本机实测出现过两个不同名字），不许把控件名钉死当验收目标。

## Acceptance criteria

- [ ] 动作执行缝可跑且零依赖：给定「目标描述 + 一帧固定尺寸合成截图 + 一份假控件树」，动作执行缝一次调用返回「动作 = 点击、最终落点、意图」，最终落点落在被选中候选的控件框内；全程不碰真实桌面、不需要凭据、不产生费用，只装标准库即可跑。失败形态：缝上跑通需要真桌面或 API key。
- [ ] 缝的假实现注入点齐备：假截图源、假控件树、假输入注入三个替身可注入（假模型响应由模型客户端那张工单提供）；换掉替身不改变缝的端口形状（输入仍是目标描述 + 一帧截图 + 可选控件树快照，输出仍是动作 + 最终落点 + 意图）。
- [ ] 换算链路必须单一来源：缩放系数只有一个真值来源（默认 1.0，含义是截图像素与物理表面像素 1:1），非 1.0 时打警告日志；单测断言——改动这一个缩放值时，所有换算入口的结果同步变化，不存在第二份不受它影响的换算逻辑。（本条断言的是「单一来源」这一契约，不指定用哪种缩放算法。）
- [ ] 抓屏后端有规矩：默认走物理像素的 GDI 抓屏路径；**禁止用 PrintWindow 顶替抓屏**（硬件加速/分层窗口会返回黑或空白，属于静默失败）；抓屏拿到 0×0 画面时跳过该捕获源（见下面哨兵值一条）。
- [ ] 同名多候选拒绝：假控件树给出两个同名候选时返回「拒绝执行 + 候选集」，注入序列为空。
- [ ] 落点误差 ≤2px（主线）：真机上对一个唯一解析出的已知按钮，最终落点与该次重读所得控件框中心的距离 ≤2 物理像素；注入后回读光标与落点一致（偏差 0），且回读值不是 (−32000,−32000) 哨兵值。失败形态：偏差 >2px 或回读为哨兵值——此项不过即不得声称闭环打通。
- [ ] C-01 启动自检：进程第一行完成 per-monitor v2 感知声明；随后屏幕物理度量 == 2560×1600、设备 caps 的逻辑 DPI == 144、抓图尺寸 == 2560×1600 且不为 0×0，三项全成立才允许进入动作层；任一不成立直接中止进程，不进动作层、不产出动作记录。
- [ ] C-02 注入自检：输入结构体大小 == 40（x64）；每次注入的返回值 == 本次注入条数；失败判定只依据返回值，不依据 GetLastError。
- [ ] C-11 点击时序：注入序列是「移动 → 停顿 ≥60ms → 按下 → 停顿 ≥40ms → 抬起」五个事件；移动与按下不得合并进同一次注入；断言用 ≥ 不用 ==（Windows 定时器精度 15.6 ms）。
- [ ] 越界不夹取：落点超出虚拟桌面边界超过 2 物理像素时，动作返回错误码（被桌面裁切），注入序列为空，既不挪到最近的显示器也不夹到边缘像素。动作的 2 px 越界容差与标定探针的 1 px 标定容差是两个独立常量，探针容差不得被当作越界容差使用。
- [ ] 多屏语义：归一化基准用虚拟桌面度量族而不是主屏度量；虚拟桌面原点为负（副屏在左或上）时落点仍然正确；归一化分母是（维度 − 1），最后一行与最后一列点得到。本机只有一块显示器，因此该判据用可注入的虚拟桌面度量构造；真机多屏回归需要第二块屏的机器，不在本单范围。
- [ ] 哨兵值与 0×0 画面：光标回读出现 (−32000,−32000) 时判执行失败并回报，不当成合法坐标；抓屏拿到 0×0 画面时跳过该捕获源，不产生落点。
- [ ] 动作集接线：协议 v1 里点击、双击、右键、移动、拖拽、滚动、输入文本、按键八类动作都有形状且可执行（能力来自已有执行层）；本单不实现的种类（放大、读控件树、执行代码、请求人工）先返回明确错误码，不做半实现——它们由后续工单按协议 v1 扩展启用。
- [ ] 双击与两次独立单击可区分：双击 = 两次单击间隔小于 500 ms 且位移小于 4 px（系统双击参数在运行时查询，不写死）；两次独立单击间隔大于 500 ms；两者产生不同的动作记录。
- [ ] 滚动量以「行」为对外单位：对外参数是行数，下发前按 ×50 换算到滚轮刻度；滚完等 300–600 ms 再取下一帧（规避滚轮惯性），等待时长可注入、可在单测里压到 0。
- [ ] 粘贴不污染剪贴板：走粘贴通道输入前备份剪贴板，动作后在 finally 路径恢复（动作后剪贴板内容与动作前一致）；粘贴通道失败时自动退回 Unicode 注入通道，而不是整步失败。
- [ ] 目标窗口被遮挡时先置前：动作作用在被其他窗口遮挡的目标窗口时，执行前先把目标置前（置前后目标窗口句柄成为前台窗口），再按落点操作。
- [ ] 只落哈希 + 恰好一条动作记录：一次动作只产出摘要（SHA-256 十六进制）而不落图像文件，落盘目录不出现任何图像文件；同帧两次摘要相同、不同帧摘要不同。每次动作恰好一条机器可解析记录，含时间、动作种类、目标（控件名与矩形）、坐标（物理表面空间）、抓图尺寸、截图哈希、结果（含错误码），并带三段耗时（定位 / 决策 / 执行+校验；本单决策段恒为 0）与三类失败字段。
- [ ] 追踪记录含「实际发送尺寸」与「图像来源」两个字段：它们是后续视觉通道判定「裁剪取自原始物理分辨率图」与「回显的是实际发送尺寸」的依据，本单随协议 v1 一起定下。
- [ ] 已知欠账如实写进记录：目标窗口完整性级别更高时注入会被拦下并返回 0，本单表现为「执行失败」（不静默放过），但不满足 C-07 要求的「零动作下发并交人」——欠到安全与审计层的工单。
