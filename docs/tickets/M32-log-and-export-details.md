## What to build

三处审计层的细节收口：

1. **M0 那条老路径的记录缺窗口标题**（D-33）：补上（真机读 `GetWindowTextW`）
2. **「窗口标题必须有值」太严**（D-36）：放宽——允许标题为空，但**必须记一条说明**（为什么没有），而不是判不合格

## Acceptance criteria

- [ ] **窗口标题补齐**：M0 那条路径产出的记录里**有窗口标题**（真机读 `GetWindowTextW`）；单测断言该路径的记录过得了字段完整性。
- [ ] **标题为空的宽严**：标题为空时**不算缺字段**，但记录里**必须有一条说明**（为什么没有标题）；单测预置「标题为空 + 有说明」→ 判合格；「标题为空 + 没说明」→ 判缺。
- [ ] **导出给 JSON Schema**：导出的机器可读格式**带一份 JSON Schema**（字段名、类型、必填性），单测断言实际导出与 Schema 一致（多一个字段、少一个字段都要被 Schema 抓到）。
- [ ] **维持现状的三条有单测钉住**：定位失败的记录**不含**「尝试过的动作」；两种落盘形状各自可用且**不合并**；`minicode.audit` 与对外 CLI 是**两个入口**（各干各的，职责不混）。
- [ ] **不动 M17 已定的字段完整性判据**：除「标题为空」这一条放宽外，其余字段的必填性**一律不变**（不许顺手放宽别的）。
