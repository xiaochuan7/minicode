## What to build

M19 的「读观察」工具**绕过动作执行缝**直接读控件树 —— 这等于**开了第二道缝**，违反 ADR-0007 写死的「唯一测试缝是动作执行缝」。

本单把 `inspect` 从「延后」挪到「已接线」：观察改走**动作执行缝**（协议里的 `inspect` 动作种类，缝不接它是因为它当时没实现；现在接上）。**12 个动作种类的集合不变**（M21 锁的是集合，不是接线状态）。

## Acceptance criteria

- [ ] **观察走缝**：`inspect` 作为动作执行缝上的一个动作种类被接线；对外的「读观察」工具**经由缝**产生，不再有绕过缝的旁路。
- [ ] **第二道缝消失**：`ActionService` 不再持有独立的 `observer` 注入依赖（那条路已经通了）；代码里**没有**任何直接读控件树的旁路——单测扫源码把住这一点（读控件树只允许出现在缝内的端口实现里）。
- [ ] **端口不新增**：观察**借用校验层已有的形状**（`verification.layer.StateObserver`），**不新立端口**（否则就是第二个接缝）。
- [ ] **C-09 不被破坏**：观察**必须带名字条件**（定点查询，禁止全树 dump）——缺 name 的请求返回 `invalid_request`，不许退化成全树查询。
- [ ] **只读**：观察不产生任何注入（假输入注入调用计数 = 0）、不产生动作记录（它是读，不是做）——但**读到的结果要有出处**（能读到它读的是哪个控件、什么矩形）。
- [ ] `inspect` 进 M21 那份「12 个动作种类」的断言（**集合不变**，只是它从"未接线"变成"已接线"）。
