## What to build

当 agent 读某个窗口的可访问性树来理解界面时，交给模型的只是一份处理过的界面状态：控件的类型、名字、位置照常保留，agent 仍看得懂自己面对的是哪个按钮；而我正在输入的聊天草稿、编辑框里的正文、密码框里的字符一律不外发——密码框在模型眼里只剩一个占位符。如果界面上恰好出现了 API key、JWT 或私钥片段，这些内容在送出之前会被替换成占位符，不会出现在模型上下文里。

这道闸不是某个通道的可选步骤：脱敏没上线，任何把控件树送进模型上下文的通道都启用不了，agent 宁可报「该通道不可用」，也不带着凭据去问模型。用户侧的可观测结果是——模型收到的界面描述里从来不会出现我的草稿、密码和凭据，而它照样能完成点按钮、找输入框这类事。

脱敏只作用于「要外发的表示」，不改动系统内部用于定位的原始数据（控件名原值、控件框物理像素）——否则密钥被替换成占位符会让两个不同控件同名，触发「唯一性拒绝」误报，也会破坏物理像素契约。

## Acceptance criteria

- [ ] 脱敏器单测全绿：给一份含五类敏感模式的树快照（密钥前缀形态、JWT 三段、长 base64、≥32 位十六进制串、私钥头），脱敏后的模型侧文本逐类断言「不出现该模式」，命中处出现固定占位符；一条命令跑完、退出码 0。该单测是纯函数单测，不引入假实现、不构成第二条缝。
- [ ] 密码框：`IsPassword=True` 的控件，其值在模型侧文本与追踪记录里一律是固定占位符；密码明文不出现在任何输出里（断言「输出不含该明文」，不依赖「恰好没被正则命中」）。
- [ ] 字段白名单：模型侧文本只含白名单字段（控件类型 / 控件名 / 自动化标识 / 控件框 / 帮助文本）；正文类控件（编辑框、文档、文本控件）的值字段不出现；快照里任何未登记的新字段一律不外发（fail-closed），不得默认放行。
- [ ] 单点出口 + 硬闸门：全仓只有一个把树变成模型侧文本的出口；该出口在「脱敏未启用」时拒绝（返回通道不可用）且不产生任何模型侧文本；单测断言默认配置（脱敏关闭）下调用该出口 → 被拒且输出为空。
- [ ] 启用期校验：配置层拒绝「送树进模型上下文已启用 + 脱敏未启用」这一组合（明确报错，不静默放过）；单测断言该组合判非法。
- [ ] 追踪记录不含密码值，且脱敏可观测：脱敏后的追踪记录里密码字段值是占位符；同时记脱敏计数（密码框替换数 / 正则命中数 / 丢弃正文类字段数 / 输出长度），使「某条通道没走脱敏」这件事能被看见。
- [ ] 缝级验证：在动作执行缝上用假控件树提供含敏感内容的树快照跑一次，断言「模型侧观察文本不含密钥模式且密码值是占位符」；全程不需要真桌面、不需要 API key、不产生费用。
