## What to build

浏览器通道现在的落点是**元素矩形中心**。在扁平 DOM 上这离文字很远——本机实测落点 (1140, 413) 而文字实际在别处，偏差大到不能当「落点」用。

本单把落点改成**可见文本的实际区域**（文本包围盒的中心）。

## Acceptance criteria

- [ ] **落点取文本区域**：浏览器通道的最终落点 = 可见文本的实际包围盒中心；元素**有**文本子节点却量不到（文本被裁 / 字体未加载 / 文本不可见）时，**判不了**（不是「落到矩形中心」也不是「随便挑一点」）。
- [ ] **偏差可判定**：真机跑一次，落点与文字实际区域中心的偏差 ≤2 物理像素（与桌面通道同一条精度线）。
  ⚠️ **「文字实际区域中心」取浏览器的**行盒**中心**（`Range.getClientRects`），**不取屏上墨迹的中心** —— 墨迹中心随字体渲染与抗锯齿抖动，行盒是稳定的布局盒（口径 2026-10-21）。
- [ ] **文本度量是新增的一层**：可见文本的实际区域要靠一层文本度量算出来；**这一层是浏览器通道独有的**，桌面通道不引入（桌面通道的落点来自控件框）。
- [ ] **不改变动作语义**：动作协议、坐标口径（物理表面空间）、错误码都不变；只改落点的取法。
- [ ] **退化可判定**：文本度量拿不到（元素**有**文本子节点却量不到：文本被裁、字体未加载）→ **判不了**并记原因，不静默回落到矩形中心。
- [ ] **没有文本子节点的元素（输入框、按钮等）落点取它自己的矩形中心**（口径 2026-10-21 补写）：屏上的字来自 `value` / `placeholder` / 默认标签时，它**不是文本节点** → 文本度量量不到。**元素框本身就是它的真值** → 落点取**它自己的矩形中心**。这**不是**「静默回落到矩形中心」（那是上一条「判不了」时禁止的事）。
  ⚠️ **与「退化可判定」那条的分界**：判不判不了看的是**有没有文本子节点**，不是「有没有量到文字」—— 有子节点却量不到 → **判不了**；压根没有子节点 → **用元素框**。
