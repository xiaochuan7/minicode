## What to build

把目标应用任务清单里 Windows 设置（W-1~W-3）与 Chrome（C-1~C-3）的 6 个任务跑通，每个任务每一步都有可判定的期望结果。

每个任务产出：跑了哪几步、每步走的通道、每步的期望断言是否成立、三段耗时与三类失败、落点误差。

需要人工确认的任务（改系统设置）按「人工代确认」方式执行，其通过情况单独统计，不混进自动通过率。

## Acceptance criteria

- [ ] W-1 通过：追踪记录里通道 = 视觉通道、UIA 侧失败类型 = 覆盖失败；读出的缩放值与界面显示一致；落点与目标控件中心偏差 ≤2 px；能力表里 Windows 设置 = 不可用。
- [ ] W-2 通过：改动后重新抓图能读到 125%；全程没有把坐标挪到最近显示器；缩放变更后要么重新自检后落点仍 ≤2 px，要么明确报错要求重新自检（不允许带着旧映射继续点）。
- [ ] W-3 通过：放大动作是回源重抓；放大后模型回答的仍是整屏坐标；落点映射回整屏后与控件中心偏差 ≤2 px。
- [ ] C-1 通过：定位依据是页面结构；动作后页面出现「职位描述」区块；动作前后快照差异里目标链接消失且详情块出现。
- [ ] C-2 通过：输入框最终值 == 目标中文关键词；提交后结果列表每条含该关键词或页面明确显示「无结果」；剪贴板用过后被恢复。
- [ ] C-3 通过：滚动以行为单位（3 行滚动不跳过整屏）；滚动后界面稳定再继续；筛选生效后列表项集合变化（城市 == 上海）。
- [ ] 报告口径：6 个任务逐个给出通过 / 失败 / 跳过与原因；人工代确认项单独统计；跳过必须写明环境原因（未登录、应用未装、网络不通），不许记为通过。
- [ ] 每步都有结构断言：不允许只用「画面变了」当通过判据。
