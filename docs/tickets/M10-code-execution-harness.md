## What to build

模型针对当前观察生成一段动作程序（可含 if/for，可调用定位与动作接口），harness 在受控环境里执行，把标准输出、异常与新截图回灌给模型。多步任务一次跑完，不用每步问一次用户。

动作协议里「执行代码」这一类动作由决策层独家产出。协议里没有「完成」这个动作值——模型自称完成不算数，终止只能由 harness 侧的停止条件承载。

动作步显式设低思考档位，规划与反思步才用高档位。历史上下文用结构摘要代替完整截图、只保留最近几张完整图，否则成本会随步数线性膨胀。

程序执行受控：只能调用动作协议暴露的动作，不允许任意系统调用与任意文件写入。

## Acceptance criteria

- [ ] 决策层产出动作程序：给定一个多步目标，模型产出的是一段程序而不是逐条动作；harness 执行后把标准输出与新观察回灌，模型据此继续；整个任务无需人工逐步确认。
- [ ] 引用纪律：实现说明与代码注释里引用 harness 增益时，只允许官方仓库 README 正文里的两组数（换 harness +19.6 分 / 步数 −53%；代码执行 vs 同等 GUI+CLI 权限 +6.1 分 / 步数 −14.8%）；另一组更宽的区间不在 README 正文正文，属禁止引用的一档——全库检索该区间，除「禁用/未核」说明句外，每一处都必须带论文消融表号。
- [ ] 协议里没有「完成」：动作协议的取值集合里不存在 finished / terminate 之类的完成动作；模型输出里出现完成类表述时 harness 不据此停止。
- [ ] 思考档位：动作步的每次模型请求都显式带低档位；规划/反思步带高档位；每条请求日志都有显式档位字段；不存在「未传档位」的调用。
- [ ] 上下文成本可控：历史帧以结构摘要承载，只保留最近 2~4 张完整截图；验收记录给出连续多步的输入 token 增长曲线，并说明它不随步数线性膨胀。
- [ ] 受控执行：动作程序只能调用动作协议暴露的动作；任意系统调用与任意文件写入被拒（单测断言：程序尝试这两类调用时被拒绝并报错，不静默放过）。
- [ ] 决策层不进单测缝：本单的验收落在端到端评测上，并如实写明「决策层没有单测覆盖」是明确承担的分工而非遗漏（缝只有动作执行缝一条）。
