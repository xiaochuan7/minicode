## What to build

M20 的敏感窗口黑名单在**抓帧之前**就把敏感窗口拦下了；M16 的十一类危险动作里有「截含敏感窗口的屏」这一类，但 M20 刻意不接 M16 的闸门 —— 结果这一类**在生产路径上永不触发**，两套口径互相遮蔽。

本单把两者接起来，顺序是 **M20 先、M16 后**（更严的一侧胜出）：敏感窗口先被黑名单挡在抓帧之前，根本走不到「截屏」这一步；M16 那一类退成**二次确认**（万一有黑名单没覆盖到的敏感窗口，审批会再问一次）。

**十一类清单不变**（不许删那一类——删了就是「合同里少一类危险动作」），只是它的触发路径从「唯一」变成「黑名单之外的兜底」。

## Acceptance criteria

- [ ] **黑名单先行**：敏感窗口黑名单命中 → **在抓帧之前**就拒绝，零抓帧、零像素产生；动作记录里如实记「被敏感窗口策略拦下」。
- [ ] **审批退成二次确认**：黑名单**没**命中但请求属于十一类里的「截含敏感窗口的屏」→ 仍然产生审批请求（带意图 + 目标），**没批则零动作下发**。
- [ ] **顺序可断言**：单测预置一个「敏感窗口 + 属于该危险类别」的输入 → 断言**先被黑名单拒**（错误码是敏感窗口策略那一类，**不是**审批未获批），且**没有走到审批闸门**。
- [ ] **两类错误码可分辨**：黑名单拒绝与审批未获批是**两个不同的错误码**，不合并（合并就丢掉了「是哪一层拦的」）。
- [ ] M16 的十一类清单**条数不变**、关键词表不变；本单只改**接线与触发路径**。
- [ ] 策略文档（由实现生成的那份）里同时写明两层：黑名单先行、审批二次确认。
