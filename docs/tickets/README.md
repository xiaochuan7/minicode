## 已在工单里写死的口径

以下几处在规格与相关决策记录之间存在互斥表述，本轮已按下列措辞**统一改到文档与工单**（改过的位置见各文件的修订清单）：

- **唯一性拒绝与消歧**（M3、M4）：**候选不唯一时先做消歧**——在 UIA 候选集内让模型**只做指认**（候选唯一时零模型调用；指认必须落在候选集内且恰好一个）。消歧失败、**候选数超过上限**（默认 8）、或指认不唯一 → 走 L4 错误处理。**任何情况下都不切视觉。**
- **标度判定与落点等价**（M5）：**落点等价判据**——标定探针给出候选标度族；只有在**存在使物理落点分歧 > 标定容差（1 px）的替代标度**时，视觉通道才不可用。分歧 ≤ 容差的等价标度族**允许继续**（等价列表必须落盘），但**标度判定**如实记为**多解**。**前提**：探针必须含最右边缘目标——0~999 与 0~1000 的物理分歧随 x 线性增长、最大值在右边缘，探针不覆盖最坏情况则本判据悄悄失效。
- **截图只落哈希**（M0）：**M0 管「落盘留什么」**（只留哈希，不落原图）；**M20 管「哪些窗口根本不许拍 / 不许发」**（发送前的黑名单 + 剪贴板读取审批）。两层不重叠。
- **0.07% 这个阈值**（M7）：它是 ScreenSpot-Pro 的**数据集统计**（目标平均占图面积，论文给出），**不是**验证过的阈值——必须做成运行时参数并记录取值来源。
- **两套命名分属不同域**（M7、M8）：**模型侧**叫「量纲分母」（只能来自运行时标定）；**目标评测脚本侧**的坐标格式常量（如 0–999 网格、`[x,y,W,H]` 宽高形式 bbox）是**输出格式**，不是量纲分母。目标脚本的取值**以脚本实际值为准并钉进单测**，不许凭二手记录取值（底稿里 ShowUI 的网格值是 0–999/1000 两说且该仓本轮未 clone 核实）。
- **冻结原型的结构例外**（口径 5）：允许对三个原型做**一次**包化改动——只动包结构与导入路径，不改任何逻辑、不改任何数值；包化前后那 50 个单测**逐个通过且输出逐字节相同**。该例外记在 `docs/00-现状.md` 的原型表里，**不写 ADR**（不满足「难逆转」，够不上 ADR 门槛）。
- **「视觉兜底层」保留**（M9）：这是规格原文的复合词，指通道的角色；**通道切换一律叫「切视觉」**，不叫兜底。

## 联网后补发 Issue 的流程

本目录是权威副本；**联网后**才把工单镜像成 GitHub Issue，流程按 `docs/agents/issue-tracker.md`：

1. 按依赖顺序发 issue：标题前缀 `M<N> `，正文用本目录对应文件的 `## What to build` / `## Acceptance criteria` / `## Blocked by` 三节原文，打 `ready-for-agent` 标签。
2. `gh` 不在 PATH 上，用全路径调用：`& "$env:ProgramFiles\GitHub CLI\gh.exe"`。
3. **阻塞边用 GitHub 原生依赖关系**：
   `gh api --method POST repos/xiaochuan7/minicode/issues/<子单号>/dependencies/blocked_by -F issue_id=<阻塞者的数据库id>`
   数据库 id 的取法：`gh api repos/xiaochuan7/minicode/issues/<阻塞者号> --jq .id`（不是 `#号`，也不是 `node_id`）。
4. **父子关系用 `sub_issues`**，它表达「这张工单属于哪个里程碑」，**不是**阻塞关系。两件事别混；要表达父子关系时才用 `sub_issues`。
