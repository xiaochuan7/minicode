## What to build

给一句目标描述（例如「任务栏的开始按钮」），系统用控件可访问性树定点查出这个目标的候选，在物理像素坐标上唯一定位到它，然后把它点下去——全程不调用任何模型，因此零费用、延迟亚秒级。落点直接取自控件自身的包围盒中心，与控件框中心的距离 ≤2 物理像素。

同名控件有多个候选时，系统不替用户挑一个：**先做消歧**——在 UIA 候选集内让模型只做指认（候选唯一时零模型调用；指认必须落在候选集内且恰好一个）；消歧失败、候选数超过上限（默认 8）、或指认不唯一 → 拒绝执行，并把每个候选的控件框和可区分 id 回报出来。执行前系统会重新读一遍树再定位一次，读不到就宁可不动作，也不会把点击打到看起来相似的另一个控件上。

树读不出东西（查询返回 0 节点）或查询超过约 5 秒时，系统报「通道不可用」而不是「目标不存在」；树能读但产不出这个目标的候选时报「覆盖失败」；候选里有却选不出时报「选择失败」——三者分开报，本单一律不切视觉。

同时系统按「应用 + 版本」把每个应用 UIA 的可用性记进能力表（三态：完全可用 / 部分覆盖 / 不可用），应用启动时判一次并静态缓存，不每步重判。

## Acceptance criteria

- [ ] 零模型调用：整个「描述 → 定位 → 点中」流程后模型调用计数为 0；追踪记录里不存在标定标度 / 粗定位点 / 裁剪计划三项（视觉通道产物）；真机侧该动作的模型请求数 = 0、记录的成本 = 0。
- [ ] 落点 ≤2px：假输入注入记录的最终落点 = 选中项控件框中心（物理像素、虚拟桌面原点）；真机端到端以鼠标位置回读值与该次重读所得控件框中心的欧氏距离 ≤2 物理像素，且落点落在被选中候选的控件框内。
- [ ] 控件框按 4 个 int 读：单测预置「若按 double 读会得到 1e-311 量级、四舍五入全 0」的候选形态，断言该形态被识别为无效坐标（不允许被当作合法左上角）。
- [ ] 全 0 候选被丢弃：包围盒四个值全 0（或退化为零面积）的候选不进候选集、不会成为选中项；丢弃后候选集为空时报覆盖失败，不得产生落点 (0,0) 的动作。
- [ ] 消歧与唯一性拒绝：候选唯一时**零模型调用**（模型调用计数 = 0）；候选不唯一时**先做消歧**——在候选集内让模型只做指认，指认必须落在候选集内且恰好一个。预置两个同名候选 + 模型未给出唯一指认（返回空 / 返回候选集外的 id / 同时指两个）→ 零输入注入（假输入注入调用计数 = 0）、结果为唯一性拒绝、回报里含两个候选各自的控件框与可区分 id。候选数超过上限（默认 8）时直接走 L4 错误处理：不调模型、零输入注入、回报候选集。任何情况下都不切视觉。
- [ ] 通道级失败两态：查询返回 0 节点 → 判「通道不可用」（不是「目标不存在」）；查询超时（约 5 秒，用可注入的假查询模拟，不真等）→ 同样按通道级失败处理。两者都不切视觉（模型调用计数仍为 0）、都零输入注入。
- [ ] 执行前重读 + 元素 id 每次观测重新生成：断言每次动作前都重新读树（假控件树读取计数 ≥2）；预置「两次观测树已变、原元素消失」→ 执行失败、零输入注入、报重定位失败；用上一次观测的元素 id 重定位必须失败。
- [ ] 只做定点查询 + 性能：发出的查询带属性条件（假控件树对无条件全树查询直接拒绝，以此禁止全树 dump）；真机单次带条件定点查询 < 1 s；端到端「定位 + 重读 + 点中」≤ 1 s，验收记录里写明用的是窗口锚定还是桌面级查询（416 ms 与 8 秒两个口径不许混用）。
- [ ] 树未就绪时退避重试：首次查询读不到树时，先激活窗口并做指数退避重试，再判定不可用——不把「第一次读不到」直接当成「不支持」；重试次数与退避时长可注入。
- [ ] 树被门控时先尝试解开：被门控的树先按已知手段尝试解开，失败才记为不可用；**三态判定本身必须稳定、可缓存**（判定只认可判定的信号：树元素数 / 可交互控件数 / 超时）；**「不可用」的归因（`gated-unlock-failed` / `no-tree`）只是观测备注，允许不稳定、允许多个候选值、必须带探测时间戳**，**不得拿归因当判定依据**。
  > **2026-10-20 实测修正**（详见 `docs/reviews/M3.md`）：真机上同一个应用两次探测的归因可能不同，且「解开失败」与「从未可用」在本机**分不开**。原 AC 要求「必须能区分」二者，与实测不符，按上面的分层口径定稿。
- [ ] 能力表三态 + 逐应用版本 + 缓存：条目键为「应用 + 版本」，取值只有完全可用 / 部分覆盖 / 不可用；同一应用在同一次启动内只探测一次（第二个动作后探测计数仍为 1）；表里至少有一条真机实测落在「部分覆盖」（Chromium/Electron 扁平树：有树、无 AutomationId、同名会撞车）；不得出现「Chromium 一律失效」「UWP 一律可用」这类类别级结论。
- [ ] 判定姿势 + 改用记事件 + 失败分类：可用性判定走递归子窗口 + 看 UIA ClassName，不数候选数（预置「裸外壳 3 个边框按钮」形态不得判为可用）；Invoke 优先，不支持 Invoke 时改用坐标点击且必须记一条改用事件；覆盖失败 / 选择失败 / 通道级失败分开报，且三类都归「定位失败」（决策层不在缝内，「决策失败」恒为空），动作下发失败才归「执行失败」；三段耗时里定位段必须有值。
