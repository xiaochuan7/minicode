## What to build

接入主链路的所有模型调用走同一个模型客户端。凭据、端点、模型、会话标识与两个必需请求头全部只从仓库的配置读，用户目录下的凭据文件不再是任何主链路代码的输入——换机器、换人只改配置不改代码。

每次请求带齐协议要求的全部头，走免费档那条通道。调用入口必须显式收到思考档位（五档，缺省即最高）：省略档位直接报错，不悄悄用最高档；动作步显式设低档，规划与反思步才用高档。每条请求写一条日志，带显式的档位字段、模型、端点、HTTP 状态、耗时、输入/输出 token 与思考 token 数。模型侧错误如实回传；HTTP 200 但没有文本输出时判为显式失败，不呈现成「成功但坐标为空」。

模型给的坐标数值原样透传：不乘分母、不按数值大小猜量纲、不裁剪到 0~1。量纲由标定探针解释，不在本单。

本单同时交付四条真调 API 的回归：缺必需头、走错通道、试图关思考、缺省档吃光 token 预算。缺一个都不合格——换网关时它们会静默失败。

## Acceptance criteria

- [ ] 凭据单一来源：端点、密钥、模型、会话标识、两个必需头全部来自仓库配置；把用户目录下的凭据文件改名或删除后重跑，客户端仍能完成一次调用；客户端内不存在第二个凭据来源。配置项缺失或为空时显式报错并指出缺哪一项，不静默回退默认值。
- [ ] 坑① 缺必需头 → Cloudflare 边缘拦截：**只去掉 `user-agent`（保留 `x-opencode-client`）→ HTTP 403**，响应体是 `error code: 1010`（**1010 是 Cloudflare 的错误编号，不是 HTTP 状态码**）；两个头都在时同一请求 HTTP 200 且拿到正常文本输出；**只去掉 `x-opencode-client`（保留 `user-agent`）同样 HTTP 200**——该头实测不被强制，保留但不作为必需项断言。
  > **2026-10-20 实测修正**（详见 `docs/reviews/M1.md`）：原 AC 写「两次调用都必须返回 HTTP 1010」——**两个头都要**这件事从未被单独测过。实测只有 `user-agent` 是必需的，且 1010 是错误编号不是状态码。按上面的实测口径定稿。
- [ ] 坑② 走错通道 → FreeTierError：基础地址换成不带免费档后缀的那条，响应体出现 FreeTierError；换回正确的那条 → HTTP 200。注意仓库配置模板里**同时存在**这两条地址，所以「选哪条」必须是可测行为，不能靠人记。
- [ ] 坑③ 试图关思考 → HTTP 400：请求体带「关闭思考」参数时返回 HTTP 400、错误类型 invalid_request_error；客户端把它作为模型侧错误如实回传，不崩、不静默改写成别的参数重试。
- [ ] 坑④ 缺省档吃光 token 预算 → 没有坐标输出：同一请求省略档位且 token 预算偏小 → HTTP 200 但响应里取不到模型给的坐标 JSON（思考链吃光预算）；此时客户端必须显式暴露「本次没有文本输出」（并在用量明细里能看到思考 token 吃满预算），不得呈现成正常成功。同一请求显式设低档、并给思考链留足余量 → HTTP 200 且拿到可解析坐标。
- [ ] 思考档位显式：档位取自五档显式枚举；调用入口省略档位即报错；只发服务端真正支持的档位字段（另一种别名写法实测被服务端忽略且更慢，不得当作正式开关）。
- [ ] 请求日志有档位字段：每发一次请求写一条日志，含档位、模型、端点、HTTP 状态、耗时、输入/输出 token、思考 token 数；档位字段值是五档之一且非空；扫描全部日志，「未显式设档位」的调用数为 0。
- [ ] 跑不通时的诚实判据：每条回归记 PASS / FAIL / SKIP。SKIP 只允许网络不可达、凭据缺失或被拒、额度耗尽或限流三种环境原因，且必须写明具体原因；其他任何原因一律记 FAIL。四条里任何一条 SKIP，整轮结论必须标「未完成（部分 SKIP）」，不得记「通过」；不许因为额度紧张就只跑其中一条。
- [ ] 缝与回归的边界写进实现说明：四条是真调 API 的**集成回归**，有单独入口，不会被单测命令带跑；单测只在动作执行缝上跑，零网络、零费用。请求构造（头集合、请求体、档位字段）可以有纯函数级单测，那不构成第二条缝。
- [ ] 坐标原样透传：客户端里不出现任何标度常量、不按数值大小选量纲的分支；分母只能来自标定结果。
- [ ] 假模型响应可预置「思考吃光预算导致无输出」的失败形态：这条形态供单测在动作执行缝上使用（它是坑④ 真调用形态的替身），单测断言系统在这种响应下判显式失败、不把空结果当成「成功但没找到」。
- [ ] 引用纪律（C-14）：任何地方写厂商自评的 61.7，必须同时标注「partial score · 厂商自评 · 官方榜无该模型条目」，且不与 binary 口径的成绩并列；对外背书只用上一代 M3 的官方榜成绩。全库检索该数字，逐处核对标注。
