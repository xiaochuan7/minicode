## What to build

在 Chromium 系应用里，定位依据是页面结构而不是像素：拿到页面的可访问性快照，按可见文本 / 角色找到目标元素，动作落在该元素上。

与桌面通道共用同一套动作语义与坐标口径：同一句目标描述在桌面应用和网页里表达同样的意图，动作协议与坐标换算只有一套。一个流程不会因为跨了技术栈就变形。

## Acceptance criteria

- [ ] 结构定位命中：在一个扁平 DOM 的真实页面上，按可见文本定位到一个元素并操作它；定位依据是页面结构快照里有该元素，不是像素比对。
- [ ] 与桌面通道同语义：同一句目标描述在桌面应用与网页里落到同类控件上，动作协议与坐标换算只有一套实现（单测断言两条通道走同一个动作与换算入口）。
- [ ] 元素引用有时效：页面变化后旧元素引用不再可用，系统重新取快照再定位，不复用过期引用（构造「页面刷新后旧引用失效」的场景，期望系统重新定位而不是报未知错误）。
- [ ] 键盘事件退化可退：浏览器收不到键盘事件时，系统退到浏览器自己的输入通道并记录这次退化，而不是整条任务失败。
- [ ] 剪贴板不污染：用粘贴通道输入后剪贴板内容被恢复（动作前后一致）。
- [ ] 能力表落位：该应用在能力表里的取值按实测填（扁平结构 → 部分覆盖），不出现「Chromium 一律失效」这类类别级结论。
  > **2026-10-21 实测修正**：原 AC 只给了「扁平结构 → 部分覆盖」的**映射**，**没给判据**——没有判据，不同实现会各判各的。本轮定下判据 =「**没有可见文本的元素数 > 有可见文本的元素数**」（本机实测 9 > 7 → 判 `sparse`）。这是本轮定的判据（见 `docs/reviews/M13.md` §5 ③）。
