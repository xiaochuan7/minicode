## What to build

三条绑在一起的事：门控的触发条件与熔断阶梯的几级现在**接的是空话**（拿不到模型报的框、接不上视觉通道参数），而**粗定位只给点、不给框**这个口径又让「目标小到值得再看一眼」和「切视觉后按框修正落点」这两件事都做不了。

本单一次把三件事接上：

1. **粗定位能报框与置信度**（改 M6 的口径「粗定位只给点不给框」——这是本单要正式改掉的那一条）
2. **门控四条条件真的能触发**（不再三条永远「不可判定」），熔断阶梯的前两级（换裁剪尺寸、换定位级别）**真的接到视觉通道参数上**
3. **切视觉后允许按控件框修正落点**（D-04：视觉通道的落点不只靠模型，可以按控件框收窄）

另外加一步**描述消歧**（D-03）：目标描述含糊时模型会点错（实测同描述两种写法落点差 1270.9 px），先消歧再定位。

⚠️ **本单依赖 M22 与 M23 的结论**：M23 判「门控不成立」的话，「按需触发」策略要退役（D-02），本单的做法要跟着改；M22 改了准入判据后，本单的门控与回落在新判据下重测。

## Acceptance criteria

- [ ] **粗定位能报框与置信度**：视觉通道的粗定位回复里带**目标框**与**置信度**（模型自报，来源串写明）；M6 的口径「粗定位只给点不给框」**正式改写**（工单 AC 同步改）。
- [ ] **门控四条条件逐条可触发**：四条条件各有一条可判定用例（不再只有一条能触发）；**不可判定**的仍如实记 `gate_undecidable`。
- [ ] **熔断阶梯前两级真的接上**：换裁剪尺寸 → 换定位级别，两级都能改变视觉通道的实际参数（单测断言参数确实变了，不只是记了一笔）。
- [ ] **切视觉后按框修正落点**：视觉通道的落点可以按控件框收窄（仍受该通道自己的精度线约束）；按什么收窄、收窄到哪，必须在追踪记录里写明。
- [ ] **描述消歧**：目标描述含糊时（预置一组会点错的描述）先消歧再定位；消歧失败 → 走错误处理，**不落到相邻那个目标上**。
- [ ] **重测 M6 的分布**：粗定位口径改了 → M6 的两级 grounding 分布**必须重测**并如实报告新旧对比（不许搬旧结论）。
- [ ] **M23 的结论已落进本单的做法**：若 M23 判门控「不成立」，本单按退役处理并写明依据。
