## What to build

第二遍精定位不是每步必做，而是命中门控才做：粗定位目标占全屏比例极小 / 粗定位输出为空或越界 / 粗定位置信度低 / 两次独立粗定位互相不一致——命中任意一条才开，不命中就直接拿粗定位结果落点（省一次模型调用，也避免在本来就找对的文字上引入漂移）。

第二遍一旦开启，若模型没给出坐标、给出越界坐标、调用失败，或精定位结果明显偏离粗定位，系统不报错中断，而是回落到粗定位结果继续执行，并记下回落原因（粗定位本身为空或越界时不存在可回落的结果，此时必须报定位失败，不得静默重试、不得落到别处）。

每一步留下可统计的痕迹：门控是否命中、命中的是哪一条、是否回落、回落原因——「门控有没有用」是事后可核对的，不靠感觉。

坐标口径统一：内部一律用原图像素，各家评测脚本互不相同的坐标期望（归一化 [0,1] / 像素 / [x,y,W,H] 宽高形式 / 0–999 网格）只在 wrapper 返回前按目标脚本转一次，并写成仓库的工程约定。

门控的实现至少落一个可核的参照并说明取舍：CCF 仓的「像素数低于阈值就不 zoom」门控 + 「失败回退粗定位」（其仓自带 220 个单测，可当回归基线）、UI-Zoomer 的「两两 IoU 均值 + 平均置信度大于阈值就不 zoom」（阈值默认 1.5）、RegionFocus 的「问模型 is this position correct? 判 YES 就不 zoom」。三者选一或融合，但必须有失败回退路径。

## Acceptance criteria

- [ ] 门控存在且四条触发条件各自独立可触发：用四个独立夹具分别只满足其中一条，四次都必须开启精定位；四者都不满足时必须不开启。额外钉死两点：粗定位只给点不给框时「目标占比」判为不可判定——不触发、也不否决其余三条，且追踪记录显式标注占比不可判定；粗定位输出为空或越界时开的是一次整屏重定位，而不是围绕粗点的裁剪窗口。
- [ ] 门控参数不是写死常量：目标占比阈值是运行时参数，取值来源被记录；凡出现 0.07% 必须标注为「数据集统计（ScreenSpot-Pro 目标平均占图面积，论文给出）、未验证的阈值」，不得写成已验证结论；置信度阈值同理。
- [ ] 粗定位回落路径可判定：精定位失败（模型无输出 / 输出越界 / 调用失败 / 结果偏离粗定位超过设定量级）→ 回落到粗定位结果并继续执行该步，追踪记录标记「回落 = 是 + 回落原因」；该步不因精定位失败而报错中断。粗定位本身为空或越界时必须报定位失败，不得落点、不得挪到最近的可行位置。
- [ ] 命中率与回落率有埋点且口径写死：每条定位追踪记录含四个字段——门控命中（是/否）、命中原因（枚举）、是否回落、回落原因；评测报告给出门控命中率（开启精定位的样本数 / 总样本数）、回落率（回落次数 / 开启精定位的样本数）、命中原因分布、样本数 N，且这四个数与该表分数用的是同一批样本。
- [ ] 坐标口径四转换有单测：一个可运行的单测模块钉死四种边界转换——原图像素 → 归一化 [0,1]（ScreenSpot-Pro 官方脚本的 point 期望）、原图像素 → 原图像素（ZoomClick 副本的 point 期望）、GT bbox [x1,y1,x2,y2] → [x,y,W,H] 宽高形式（CCF 仓 ScreenSpot-v2 脚本）、原图像素 → 0–999 网格（ShowUI 脚本）；每种至少一个具体数值例子，并各带一个反例（把 [x,y,W,H] 当 [x1,y1,x2,y2] 判定会得出相反结论）。
- [ ] 接官方脚本的防假象自检：把 GT bbox 中心当作预测点喂给自己的 wrapper，目标脚本给出的命中率必须接近 100%，不是 0——这是「接了官方脚本但分数全 0」那类假象的自检。
- [ ] 口径约定落进仓库的工程约定（决策记录体例 + 约定文档一行指路），不写进词汇表（词汇表只定义词义）；评测目标脚本的格式常量（0–999 网格、宽高形式 bbox）与模型量纲分母必须分属两套命名、来源可区分。
- [ ] ShowUI 网格值以实际脚本为准核一次并钉死：底稿记的是 0–999/1000 两说且该仓本轮未 clone 核实；0–999 与 0–1000 在 2560 宽上只差 2.56 px，落错一档不报错、只会让分数悄悄低一点——实现时必须读实际脚本确定，并把结论写进注释与单测。
- [ ] 门控的参照落地：至少实现一个可核参照（CCF 的「像素数低于阈值不 zoom」门控 + 「失败回退粗定位」／UI-Zoomer 的「IoU 均值 + 平均置信度大于 1.5 就不 zoom」／RegionFocus 的「问模型 is this position correct? 判 YES 就不 zoom」），并在实现说明里写明取舍理由；**必须有失败回退路径**。
- [ ] 门控不是切视觉的理由：切视觉仍只认覆盖失败；本单的门控只在视觉通道内部生效。
