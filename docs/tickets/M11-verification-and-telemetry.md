## What to build

每一步动作之后，系统自己确认界面确实按预期变了。用户可以对自己的目标写一句可判定的期望（某个按钮变成不可用、某段文本出现），系统执行后自动断言。

没有期望时也要做默认校验：动作前后抓帧做差分，变化率低于 1% 且持续两帧就报「界面无变化」。但「无变化 ≠ 失败」、「像素变化 ≠ 成功」——点错打开错对话框也会安定，所以变化检测只能当必要条件，不能当充分条件。

效果验证三手段按可靠性排序取并：可访问性树（查状态 / 存在性 / 矩形变化）＞ 文本比对 ＞ 像素差分；判据取三者的或，且刻意不让模型当裁判。

每一步日志里同时记下定位 / 决策 / 执行+校验三段耗时与定位失败 / 决策失败 / 执行失败三类失败——否则任务掉了不知道该改哪一层。

## Acceptance criteria

- [ ] 期望断言可判定：给一个可判定的期望（状态变化 / 文本出现），动作后自动断言并返回通过或失败；断言失败时结果里能读到期望内容与实际观测的差异。
- [ ] 无期望时的默认校验：动作前抓基线帧、动作后轮询（首次立即 + 100 ms 内 15 ms 节奏 + 之后 20 Hz），比较用 8×8 像素块 + 32 位精确比较，判定顺序「有反应 → 安定 → 返回」，阈值 1% 像素变化；变化率低于 1% 且持续两帧 → 报「界面无变化」。
- [ ] 两条语义边界各有可复现用例：故意点错打开另一个对话框（画面变化并安定）→ 系统不得判成功；界面本来就无变化（如对已置位控件再点一次）→ 系统不得直接判失败。
- [ ] 三段耗时齐全：每步日志里定位 / 决策 / 执行+校验三段分别有值；单步与整任务都能读出三段占比。
- [ ] 三类失败分开统计：定位失败 / 决策失败 / 执行失败各自计数、互不混淆；一次任务跑完后能给出三类各自的次数与占比（不是笼统的「失败 N 次」）。
- [ ] 验证手段的优先级生效：可访问性树能判的场景不以像素差分作为唯一判据；判据取三者的或，且模型不参与裁判。
- [ ] 追踪记录与动作日志：追踪记录走可注入的旁路出口，不进主返回类型；动作日志字段含时间、动作类型、目标窗口句柄与标题、落点坐标（物理表面空间）、截图哈希、动作前后状态、结果。
