## What to build

先做一次整屏粗定位得到大致位置，再以它为中心取一块 512×512 物理像素窗口，从原始物理分辨率图上 1:1 裁下、放大给模型做精定位。最终落点只在 crop 尺度上产生；整屏归一化坐标只用来「选哪块区域」，永远不直接点击。

坐标契约是「crop 内坐标 + 原点偏移」，不是「模型在放大图里仍报整屏坐标」那套——后者的前提是模型被训练过，本项目所用的模型没有被训练过，两套混用会让落点偏一整个裁剪窗口，而且是静默偏移。

裁剪窗口越界时用平移或缩小（平移保尺寸、尺寸不足时缩小），不夹取——夹取会把目标裁出窗口。精定位失败时能回落到粗定位结果。每步回显模型自己发出的坐标与实际发送尺寸，让模型能对账自己的坐标。

## Acceptance criteria

- [ ] 裁剪源正确（C-06）：裁剪窗口取自原始物理分辨率截图，不是降采样图；单测能判定「裁剪来源」这一属性（用一张带已知细节的合成帧——「降采样后再上采样」与「直接裁原始图」的像素不同，据此区分）。
- [ ] 裁剪计划不裁掉目标：目标靠近边缘时裁剪窗口平移保尺寸，表面不够大时缩小；目标完整落在窗口内（裁剪计划暴露「目标是否完整包含」这一属性并被单测钉死）。
- [ ] crop 契约（crop 内坐标 + 原点偏移）：模型在 crop 内报 0~1000 归一化的坐标，映射回物理表面空间后与直接在该区域定位的落点一致；存在物理像素 → crop 内 → 物理像素的往返自检，单测断言往返误差为 0。
- [ ] 粗定位回落：精定位失败（无输出 / 输出越界 / 调用失败）→ 回到粗定位结果并继续执行该步，追踪记录标记回落与回落原因；粗定位本身为空或越界时不存在可回落结果，必须报定位失败，不得静默重试、不得落点、不得挪到最近的可行位置。
- [ ] 每步回显：回显里能读到「模型发出的坐标 + 实际发送尺寸（宽×高）」；实际发送尺寸取的是实际发出的那张图，不是原图宽、也不是写死的常量；代码里不出现任何写死的图像像素上限常量。
- [ ] 放大动作与裁剪不是一回事（两者都归本单，因为都依赖视觉与抓屏，但契约不同）：放大是动作协议里的一个动作——指定区域**回源重抓**后送模型看清楚，模型回答的仍是**整屏坐标**；裁剪是两级定位内部的取景——从原始物理分辨率图取窗口，模型报 **crop 内坐标**，由系统加裁剪原点偏移映射回全屏。单测断言放大路径不经过裁剪计划（放大的是回源重抓的物理画面，不是降采样产物）。
- [ ] 分母来自标定：换算链路的分母只能来自标定结果；代码里不出现写死的 1000/999，也不按数值大小猜量纲。
- [ ] 追踪记录可判定：记录里能读到粗定位点、裁剪计划、最终落点、实际发送尺寸与图像来源——这四项是判定「裁剪取自原始物理分辨率图」与「回显的是实际发送尺寸」的依据。
- [ ] 真机分布回归：在一组目标上（至少 10 个，含 ≤16 px 的小图标）统计落点误差分布，而不是只报单次数字（本机同一目标的单次粗定位误差在 3.4~7.6 px 之间浮动，单次数字不能当验收线）；判据用一组目标的分布，并要求精定位那一级的分布不劣于粗定位。
