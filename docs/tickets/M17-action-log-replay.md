## What to build

动作日志能完整回放每一步：出事故后能看到「它当时以为自己在干什么」。

日志可导出成机器可读格式，供自己离线统计与回放分析。

日志字段完整且不含敏感内容：只落截图哈希不落原图。

## Acceptance criteria

- [ ] 字段完整（**按动作种类的合格**，不是「每条记录七样都有」）：需要落点的动作种类（`POINT_KINDS`）必须有落点、且空间是**物理表面空间**；不需要落点的动作种类（`screenshot` / `wait`）必须**没有**落点；**定位阶段就失败的步骤没有下发动作 → 记录里没有动作类型是如实的**（动作压根没构造出来）；**动作下发过却没有动作类型 = 缺字段**。其余字段（时间、目标窗口句柄与标题、截图哈希、动作前后状态、结果含错误码）每条都要有，缺即不合格。
  > **2026-10-21 实测修正**：原 AC 的字面读法会让「定位阶段就失败的步骤」永远不合格（那种步骤没有下发动作 → 没有动作类型、没有落点、没有窗口句柄）——那不是缺字段，是**如实**。
- [ ] 可回放：用日志能重放出每一步的动作与结果，且重放结果与当时的记录一致（回放是动作日志层面的可回溯，不是「录一段屏再回放」）。
- [ ] 机器可读导出：导出格式可被脚本解析，且从导出文件能算出成功率、三类失败分布、三段耗时分布（不依赖人工看）。
- [ ] 截图只落哈希：日志与导出里只有截图哈希，没有图像内容。
- [ ] 敏感内容不外泄：日志里不出现密码、密钥等模式的明文（用脱敏器同一套规则检查）。
