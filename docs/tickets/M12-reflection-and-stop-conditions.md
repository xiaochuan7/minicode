## What to build

任务不会在死循环里点一整夜：某个策略连续无效时系统自己换策略；到了步数上限，或遇到无法安全自动处理的场景（如提权弹窗），就停下来交给人，并把轨迹交出去。

四类卡死检测器：帧无变化、重复动作、进度停滞、轮次硬上限。停止条件由 harness 强制，模型自称完成不算数。

重试策略：只重试可逆动作；发消息、支付、删除这类不可逆动作不可自动重试；重试带退避与上限（3 次，200 / 500 / 1200 ms）；每次重试前必须重新感知（复用旧坐标 = 误点）；用状态机而不是脚本。

模型自评置信度不得作为危险动作的放行条件：实测存在高置信度的错误，且答对时的置信度均值反而低于答错时，绝对值不可当把握度，排序可用。

## Acceptance criteria

- [ ] 重复动作熔断：同一动作哈希连续 ≥3 次且帧无变化 → 强制换策略（换裁剪尺寸 / 换定位级别 / 改键盘 / 请求人工）；该场景可复现（构造一个点了不动的目标），并能读到「已换策略」的记录。
  > **2026-10-21 实测修正**：本单的三个阈值（帧无变化 ≥2 步 / 进度停滞 ≥3 轮 / 重复动作 ≥3 次）都是**工程阈值·未验证**——取值来源必须随判定一起落盘，不许写成已验证的结论。
- [ ] 轮次硬上限：达到上限时任务停止并交人，停止原因写明是轮次上限；模型自称完成不构成停止理由（构造模型提前宣称完成的响应，期望系统继续执行到上限或到期望断言成立）。
- [ ] 重试只针对可逆动作：移动 / 滚动 / 聚焦失败时按退避上限 3 次（200 / 500 / 1200 ms）重试；发消息 / 支付 / 删除失败时没有自动重试（注入记录里重试次数 = 0）。
- [ ] 重试前重新感知：预置「第一次尝试后界面已变」的场景 → 期望重试走的是重新感知后的新坐标，复用旧坐标的那条路径不允许发生（单测断言注入的坐标不等于上一次的旧坐标）。
- [ ] 四类卡死检测器齐备：帧无变化、重复动作、进度停滞、轮次硬上限各有一条可复现的用例。
- [ ] 提权场景零动作交人：检测到提权 / 安全桌面时注入序列为空、返回「交接给人」；日志里有一条「已交接给人」的记录；代码里没有默认开启「降低提权安全级别」的路径（该路径必须由用户书面同意才存在）。
- [ ] 交接产物可读：交给人的内容含当前窗口标题、最后一步动作、已发坐标与已执行动作清单，人能看懂发生了什么。
- [ ] 置信度不作放行条件：任何危险动作的放行判据里不出现模型自评置信度；构造一个高置信度但错误的场景，期望仍需人工确认。
- [ ] 边界写清：危险动作审批与 dry-run 属于后置的安全与审计工单，本单只做「检测 + 停手 + 交接」，不假装已做审批。
