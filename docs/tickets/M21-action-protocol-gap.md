## What to build

动作协议 `cua.action/1` 的**动作种类集合以「架构决策备忘」§3 的 12 个为准**：screenshot / click / move / drag / type / key / scroll / wait / zoom / inspect / execute_code / ask_user。**双击与右键是 `click` 的参数**（`click_count` / `button`），不是独立动作种类。

M0 已经接线了这 12 个里的 10 个，**只缺 `screenshot` 与 `wait` 两个**。本单把这两个补上，让协议的动作种类集合与架构决策备忘逐字对齐，并**加一条断言把这份集合锁死**——防止以后再漂移出第 13 个动作种类。

使用者的可观测结果：模型或人发一条「截一张图」或「等 300 ms」，协议给出形状正确的动作并能跑通，不再退回「暂不支持」；协议里不再出现与架构决策备忘对不上的动作种类名。

本单是**纯软件单**：不碰真实桌面、不需要 API key、不产生费用。

## Acceptance criteria

- [ ] `screenshot` 形状正确：参数 `region?`——给了就是一块**物理像素**矩形，不给就是整屏；单测断言「给了 region」与「不给 region」两种形态的参数形状与动作结果。
- [ ] `wait` 形状正确：参数 `ms`（毫秒）；单测断言等待时长**可注入**、可在单测里压到 0，不产生真实长等待。
- [ ] 两个动作各有单测：`screenshot` 与 `wait` 各有至少一条单测，只断言对外可见的契约字段（动作种类、参数、结果、错误码），不断言内部算法。
- [ ] 错误码与结果枚举与现有协议一致：两个新动作复用现有 `ActionResult` 与既有错误码枚举，不另起一套；协议版本号仍是 `cua.action/1`，**不升版本**。
- [ ] **动作集合锁死**：加一条单测断言「协议的动作种类集合 == 架构决策备忘 §3 的 12 个」（逐个比对名字），集合多一个或少一个都判失败——这条断言是本单的防漂移闸门。
- [ ] 双击与右键收敛为 `click` 的参数：`click` 的参数含 `click_count`（1 = 单击，2 = 双击）与 `button`（1 = 左键，3 = 右键）；协议里**不再有**独立的双击 / 右键动作种类。既有行为保持不变——双击与两次独立单击仍产生不同的动作记录（靠参数区分，不靠动作种类区分）。
- [ ] 输入文本的动作种类名为 `type`（与架构决策备忘 §3 逐字一致）。
- [ ] 缝级验证：在动作执行缝上用假实现跑一次 `screenshot` 与 `wait`，断言返回的「动作 + 最终落点 + 意图」形状与既有动作一致；全程不碰真实桌面、不需要凭据、不产生费用。
