## What to build

删除、支付、发消息、注册、改系统设置、跑命令行这类动作必须先经人工确认。审批请求写清楚「要做什么」和「对哪个目标」——确认的是这一条具体动作，不是笼统的「继续」。

不可逆动作在真正执行前先把将要作用的对象呈现出来（dry-run），让人能看出它点的是不是自己想的那个。

遇到提权弹窗零动作下发，把轨迹交人。系统默认永不降低提权安全级别——关掉安全桌面提示必须由用户书面同意才能开启。读剪贴板前先问。

模型自评置信度不作为危险动作的放行条件。

## Acceptance criteria

- [ ] 危险动作清单生效：删除、支付、发消息、注册、改系统设置、运行命令行、安装软件、改注册表、提权弹窗、读剪贴板、截含敏感窗口的屏——每类在执行前都产生审批请求，不存在静默执行的类别。
  > **2026-10-21 实测修正**：① 十一类**不变**（M20 不得删掉其中任何一类——删了就是合同里少一类危险动作）；② 「截含敏感窗口的屏」这一类在生产路径上**由 M20 的黑名单先行拦截**（黑名单在抓帧前就拦，**更严的一侧胜出**），M16 这一层退成**二次确认**（接线待 **M24**）；③ 分类是**关键词命中即生效**，**中英文都要有**（模型有时写英文意图），M12 的不可逆词表是本清单的**子集**；④ 关键词表是**工程阈值·未验证**（没有语料统计过误报率），取值来源随判定落盘。
- [ ] 审批绑定意图 + 目标：审批请求里同时含「要做什么」与「对哪个目标」（可定位到具体控件 / 窗口）；审批结论绑定到这一次动作，不是一次性授权后续同类动作。
- [ ] dry-run：不可逆动作执行前先呈现将要作用的对象（目标控件的框、位置与截图哈希），确认后才真正执行；未确认时零动作下发。
- [ ] 提权场景：检测到提权 / 安全桌面 → 零动作下发 + 交人 + 日志里有「已交接给人」；代码里没有默认开启「降低提权安全级别」的路径（该路径必须由用户书面同意才存在）。
- [ ] 置信度不作放行条件：危险动作的放行判据里不出现模型自评置信度；构造一个高置信度但错误的场景，期望仍需人工确认。
- [ ] 读剪贴板需审批：读取剪贴板内容前产生审批请求；未获批不读取。
