## 0. 一句话结论

**停止条件落成了机器可判的状态机**：四类**卡死检测器**（帧无变化 / 重复动作 /
进度停滞 / 轮次硬上限）各自吃**一种信号**；命中**先换策略**（熔断：换裁剪尺寸 →
换定位级别 → 改键盘 → 请求人工），**只有轮次上限 / 目标级期望成立 / 程序请求人工 /
提权 / 危险动作**才终止任务并把**交接产物**交出去（窗口标题 / 最后一步动作 /
已发坐标 / 已执行动作清单）。**重试只针对可逆动作**（移动 / 滚动 / 聚焦），
退避 **200 / 500 / 1200 ms**（上限 3 次），**每次重试前重新感知** —— 重试走的是
重新走一遍动作执行缝（重新定位 → **新坐标**）。**提权 / 安全桌面一律零动作下发**
（C-07），结果与动作记录里有一条「**已交接给人**」。**模型自评置信度不出现**在任何
放行判据里（单测扫源码把住）。

## 2. 设计

### 2.1 四类检测器：**各管一种信号**（因此不会互相顶替）

| 检测器 | 粒度 | 判据 | 命中后 |
|---|---|---|---|
| 帧无变化 | 步 | 这一步做完**界面没变**（取 M11 默认校验的结论） | 只记录（与重复动作**同时**命中才熔断） |
| 重复动作 | 步 | **同一动作哈希**连续出现（种类 + 目标描述，**不含坐标**） | 与帧无变化同时命中 → **熔断换策略** |
| 进度停滞 | 轮 | 连续 N 轮**既没期望成立、也没界面变化** | **换策略** |
| 轮次硬上限 | 轮 | 轮数到上限 | **停止 + 交人** |

### 2.2 检测器 ≠ 停止条件

工单把四类检测器与停止条件并列，但两者**不是一回事**：
检测器命中**先换策略**（「某个策略连续无效时系统自己换策略」），
**只有**轮次上限 / 目标级期望成立 / 程序请求人工 / 提权 / 危险动作才终止。
否则 AC2 的「继续执行到上限」会被「停滞」提前截断（两轴审查抓到的正是这一点）。

### 2.3 熔断 = 换策略，阶梯走完 = 交人

阶梯：换裁剪尺寸 → 换定位级别 → 改键盘 → **请求人工**。
每次换策略都产出一条记录（「已换策略（第 N 次）：换定位级别 —— 同一动作连续 3 次且界面无变化」），
并**写进上下文** —— 下一轮模型看得见它，据此换招（单测断言提示词里出现「已换策略」）。
走到「请求人工」那一档 = **停下来交人**。

### 2.4 重试：**只重试可逆动作**，且**重新感知**

* **可逆性**：动作种类白名单（`move` / `scroll`）+ 点击（目标不命中不可逆词表）；
  **其余一律不可逆**（fail-closed）。
* **退避**：200 / 500 / 1200 ms，**上限 3 次**（不含首次尝试）。
* **重新感知**：重试是**重新走一遍动作执行缝** —— 重新定位 → 新坐标；
  上一帧画面与上一份控件树快照**丢掉**（不复用旧坐标的那条路径不存在）。

### 2.5 提权 / 安全桌面：**零动作交人**

Windows 上「提权弹窗」= **安全桌面**（输入桌面被切到 `Winlogon`）。
检测问「输入桌面的名字」；**读不到**时**按提权处理**（fail-closed）——
安全桌面上 `OpenInputDesktop` 恰恰会返回 `ACCESS_DENIED`，
那正是要判的场景（两轴审查抓到的 fail-open）。
**代码里没有**任何改 `PromptOnSecureDesktop` 的路径（单测扫全仓把住）。

### 2.6 交接产物：四样 + 一份调用记录

当前窗口标题 / 最后一步动作 / 已发坐标 / 已执行动作清单，
外加**接口调用记录**（定位失败的那些尝试也在里面 —— 人要看得出最后在干什么）。

## 4. 与工单假设不符的现实（12 条）

1. **「四类卡死检测器」工单没给判据** —— 本轮自己定了四条（§2.1），
   全部标成**工程阈值·未验证**（帧无变化 ≥2 步 / 重复动作 ≥3 次 / 停滞 ≥3 轮），
   并记进 §5 待拍板。
2. **「同一动作哈希」工单没说哈希算什么** —— 取**动作种类 + 目标描述**
   （**不含坐标**：重新感知之后坐标会变，而「同一个动作」指「同一件事」）。
3. **「进度停滞」没有现成信号** —— 定义成「连续 N 轮**既没期望成立、也没界面变化**」
   （界面变了但期望一直不成立**不算**停滞：那叫「还在努力」）。
4. **「换策略」的四个选项有两个动不了** —— 「换裁剪尺寸 / 换定位级别」是
   **视觉通道的内部参数**（M6/M7 的 crop 窗口与门控），本轮**没有**去动它们
   （会改已上线的通道，且「切视觉」有红线）。因此换策略目前是
   **把策略写进上下文让模型换招 + 留记录**，「请求人工」那一档会真的停下来交人。
   → §5.3。
5. **「重试只针对可逆动作」里的「可逆」没有机器判据** —— 用「动作种类白名单 +
   不可逆词表」fail-closed（§2.4）。「聚焦」落在「点击且目标不是发消息/支付/删除」这一档。
6. **「每次重试前必须重新感知」在实现上就是「重新走一遍缝」** —— 重试调用的是
   **同一个动作执行缝**（不是重放动作），所以定位、置前、校验全都重来一遍。
7. **「提权弹窗」在 Windows 上是安全桌面** —— 检测靠**输入桌面的名字**（`Winlogon`）；
   ⚠️ 安全桌面上 `OpenInputDesktop` 会**失败**（`ACCESS_DENIED`），
   所以「读不到」必须**按提权处理**（fail-closed），不能当成「没提权」。
8. **「置信度」工单给的是实测事实**（高置信度有错、答对时均值反而低于答错时）——
   因此判据里**一个置信度字样都不许有**（单测扫源码），
   并且**危险动作的审批不在本票**（M16）：本票只做「检测 + 停手 + 交接」。
9. **「协议里没有完成」** —— 协议里本来就没有；本轮把「停止原因」细分成六种
   （`round_cap_reached` / `expectation_met` / `asked_human` / `elevated` /
   `strategy_exhausted` / `dangerous_action`）。
10. **「停止原因 round_cap」与检测器 id 同名** —— 改成 `round_cap_reached`
    （一个是检测器，一个是停止原因；`CONTEXT.md` 说熔断与停止条件不许混）。
11. **目标级期望来自 M11 的欠账，不是本票新增的需求** —— M11 §5.7 明写
    「用户对整个目标写一句期望、由 harness 决定它落在哪一步，是 M12 的活」；
    本轮的实现口径是「**跟着每一步走**」（§5.2）。
12. **决策层「没有单测」的分工被本票改了一部分** —— M10 的分工是
    「决策层（模型产出程序、循环推进、上下文裁剪）没有单测覆盖」。
    本票把**停止条件**落成**独立的状态机**（`reflection/stop.py`）：
    它**没有模型依赖**、不碰桌面，因此**有单测**；
    **规划质量**那一半仍由端到端评测承担（分工没变）。

## 7. 测试与评测的分工

* **单测**（`src/minicode/reflection/test_reflection.py`，**42 条**）覆盖九条验收标准的
  **外部行为**：熔断与记录、轮次上限与「自称完成不算数」、重试的可逆性与退避表、
  重试换新坐标、四类检测器各一条、提权零动作交人（含 fail-closed 与「没有降安全
