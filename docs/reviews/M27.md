## 3. 与工单假设不符的现实 / 需要人拍板

1. **OCR 会把 `%` 认成全角 `％`、把字里加空格、`l`/`I` 混淆**（实测 `ScaIe 150 ％`）。
   比对前加了一道**只作用于 OCR 这一路**的归一（`ocr.py:125` `normalize_ocr_text`：
   NFKC + 去全部空白 + 小写）；**树里那一路的文本比对口径一个字没改**
   （`action/text.py` 在边界外，没碰）。⚠️ **「l↔I」这类真错字归一救不了** ——
   目标文本里含字母时要当心。
2. **「接了 OCR 之后，画面这一路是权威的」是本单立的口径** → **2026-10-21 已拍板接受**：
   树覆盖不全时「树里没有」**不能**说「期望不成立」。判据：**OCR 读到了 → 按画面判；
   OCR 读不出 → 判不了；没接 OCR 端口 → 保持 M11 原口径**。
3. **「读到但一个字都没读出来」判成「判不了」** —— 空读数可能是识别失败（空白区 / 字体太小），
   拿它说「期望不成立」是危险的。**代价**：OCR 只能证明「它在那儿」，
   不能单凭空读数证明「它不在这儿」。
4. **「期望」是变化语义**（M11 的口径），所以稳定读数（聊天区标题、缩放值）要用「出现」判
   就必须有个「之前不在画面上」的基线。真机跑的就是这个基线→出现的过渡。
   若要的是「此刻它就在那儿」，现有三种形态里**没有**这种断言 —— **要不要加一档请拍板**
   （本单**没有**加）。
5. **Windows 自带 OCR 的可用语言包**：本机只有 `en-GB` / `en-US` / `zh-Hans-CN`
   （读中文界面用 `zh-Hans-CN`）。`pytesseract` 装着但**没有 tesseract 可执行文件**，
   **没装**；`paddleocr` / `paddlepaddle` 装着但**模型没缓存**（要联网下载），也没用它 ——
   走系统自带 OCR 一条路，**没给项目引新依赖**。
6. **`Windows.Media.Ocr` 只能从 Windows PowerShell 5.1 调到**（PS7 的 WinRT 投影不可用），
   所以真机后端是「python → `powershell.exe` → WinRT」（`ocr_windows.py:84` `_powershell`）。
   实测单次读 **420~510 ms**（每读一次起一个进程）→ **每步校验多约 1 秒**。
7. **`e2e/` 那条路还没接 OCR** —— 端到端执行器（`src/minicode/e2e/real.py` / `apps.py`）
   在**边界外**，本单没动。要让 M14/M15 的 W-1②/WX-1③ 在端到端流程里也自动成立，
   需要接线 `VerificationLayer(ocr_port=WindowsOcrPort())` + `VerifyRequest.ocr_region`
   → **已开 M34**。
