## 2. 设计

### 2.1 一份实现，两个前端

```
              ┌──────────────────────────┐
命令行前端 ──→│  ActionService.execute   │──→ 动作执行缝 ──→ 落点 + 动作记录
HTTP 前端  ──→│  （唯一的一份）          │        │
              └──────────────────────────┘        ↓
                                          动作日志（ActionLog）
```

* `serve/protocol.py` —— **动作请求 / 动作响应**的外部形状 + 版本核对；
* `serve/service.py` —— **唯一入口实现**（`ActionService.execute`）；
* `serve/cli.py` —— 命令行前端（`action` / `log` / `http` 三个子命令）；
* `serve/http.py` —— HTTP 前端（`POST /v1/actions`）；
* `serve/real.py` —— 真机接线（复用 `uia/desktop.py`）；
* `serve/fakes.py` —— 假桌面接线。

两个前端都**只做「解析 → 调它 → 渲染」** —— 动作语义、坐标口径、错误码**各只有一份**。

### 2.2 真机接线抽成一份（`uia/desktop.py`）

原先真机 UIA 接线写在 `uia/__main__.py::_run` 里；本轮抽到
`uia/desktop.py::build_desktop`（`:113`），**`uia/__main__.py` 与 `serve/real.py` 都调它**。
接线内容：窗口锚点 → 定点查询端口 → 能力表 → UIA 通道 → 动作执行缝，
外加**提权检测**（C-07）与**审批闸门**（M16）—— 对外形态**没有绕过安全闸门**。

### 2.3 HTTP 状态码与协议错误码是两层

| HTTP | 什么时候 | 响应体的 `error_code` |
|---|---|---|
| 200 | 请求**被受理并执行了**（动作成功与否看 `ok`） | 动作层的协议错误码（如 `target_not_found`） |
| 400 | **请求层**被拒（版本对不上 / 形状不对 / 动作种类这一层不接）→ 零动作下发 | `protocol_version_mismatch` / `invalid_request` / `action_not_implemented` |
| 404 / 405 | 路径不对 / 方法不对 | `invalid_request` |

⚠️ **每条响应都是同一个形状**（`protocol_version` / `ok` / `error_code` /
`error_message` / `action` / `landing_point` / `record`）——
连 404 与 405 也是（`serve/http.py:61` 的 `_rejected`）→ 调用方**只有一种解析方式**。

### 3.1 假桌面（2026-10-21，不碰真桌面、不调模型、不花钱，`runs/m18/`）

```
=== 命令行 ===
$env:PYTHONPATH="src"; python -m minicode.serve action --target "开始" --fake --out runs/m18/cli --json
退出码：0
{"protocol_version": "cua.action/1", "ok": true, "error_code": null,
 "action": {"kind": "click", "params": {"x": 1049, "y": 1564, "space": "physical-surface"}},
 "landing_point": [1049, 1564], "record": {...}}

$env:PYTHONPATH="src"; python -m minicode.serve log --out runs/m18/cli --json
退出码：0｜日志条数：2
  cua.action/1 click 开始 | ok=True  | 落点=(1049, 1564)
  cua.action/1 <无动作>  | ok=False | 落点=（无）  ← 目标找不到（error_code=target_not_found）

失败那次的退出码：1（成功是 0）｜ok=False｜错误码=target_not_found

=== HTTP（同一台机器上起服务） ===
POST /v1/actions → 200
{"protocol_version": "cua.action/1", "ok": true, "landing_point": [1049, 1564], ...}
动作失败（目标找不到）→ 200｜ok=False｜错误码=target_not_found（**是协议里的取值**）

  错误信息：协议版本不匹配：请求 cua.action/0，本实现只支持 cua.action/1
  下发的输入事件数：0（**零动作下发**）

=== 两条入口的语义一致（同一请求 → 同一动作与落点）===
命令行：action={'kind': 'click', 'params': {'x': 1049, 'y': 1564, ...}} 落点=[1049, 1564]
HTTP ：action={'kind': 'click', 'params': {'x': 1049, 'y': 1564, ...}} 落点=[1049, 1564]
动作一致：True｜落点一致：True
```

产物：`runs/m18/cli/action-records.jsonl`（2 条）、`runs/m18/http/action-records.jsonl`（2 条）——
两条入口的记录**形状同构**（字段集合一致），且**落点与错误码逐字相同**
（`(1049, 1564)` / `target_not_found`）。
⚠️ **时间戳与三段耗时当然不同**（那是两次独立执行，各自有各自的时刻）——
「语义一致」指的是**动作与落点**一致，不是整条记录逐字相同。

## 4. 与工单假设不符的现实（8 条）

1. **工单说「CLI 与 HTTP」，但没说清「谁是主人」** —— 本轮把**唯一入口实现**放在
   `serve/service.py`，两个前端只是壳。工单原话「同一入口实现，不是两份」
   （AC3）被落成**结构**（两个前端都只能调 `ActionService.execute`），
   而不是靠约定。
2. **工单没提「动作种类」** —— 动作协议有 **12** 个种类，但**动作执行缝只接 7 个**
   （需要落点的 4 个 + 截图/等待 2 个 + 放大 1 个）；`type` / `key` / `inspect` /
   `execute_code` / `ask_user` 缝**不接**。本轮的做法是在**请求层**就说清楚
   （`action_not_implemented`），**不许异常逃到前端**（两轴审查抓出来的，见 §8）。
3. **「坐标由谁给」工单没写** —— 坐标**不由调用方给**（给了也不认）：落点只由
   动作执行缝给（`serve/protocol.py` 的字段表里**没有**坐标字段）。
4. **`target` 不是所有种类都要** —— 截图 / 等待**不需要定位目标**
   （协议里它们是「独立」动作种类）；**放大也不需要**（它的落点来自
   `params["region"]`，目标描述只进意图串）。工单没写，本轮按协议来：
   `NEEDS_TARGET_KINDS`（`action/protocol.py`，= `POINT_KINDS`）→
   `serve/protocol.py:70` 的 `_NEEDS_TARGET_VALUES`。
5. **假桌面与真机走的是两条不同的定位路径** —— 假桌面走 **M0 老路径**
   （控件树 + 截图像素空间取中心再 `floor`），真机走 **UIA 通道**
   （控件框中心 + **就近**取整）。同一块控件，假桌面给 **1049**、真机给 **1050**
   —— **差 1 px，取整口径本就不同**。⚠️ 这不是本轮引入的（是两条既有路径的差别），
   但它让「假桌面的落点常量」不能照抄 `center_point`（本轮踩过一次，见 §8 J3）。
6. **HTTP 状态码与协议错误码是两件事** —— 工单只说「错误码与协议里的取值一致」，
   没说 HTTP 状态码怎么办。本轮的口径：**请求层被拒 → 400；动作层失败 → 200**
   （请求被受理并执行了，失败是动作层的事实）。→ 已登记进
   `docs/tickets/README.md` 的口径清单。
7. **`log` 子命令不需要桌面** —— 读动作日志是**只读文件**（`ActionLog.records()`），
   不该为此造一整套假桌面（两轴审查 J7）。
8. **HTTP 服务跑在命令行里，服务端的请求日志要看得见** —— 沿用 M16 的做法
   （审批人在命令行里问人），`http.log_message` 直接打标准输出。

## 7. 测试与评测的分工

* **单测**（`src/minicode/serve/test_serve.py`，**19 条 + 15 个 subtest**）覆盖四条
  验收标准的**外部行为**：命令行的退出码与输出、HTTP 的状态码与响应体、
  两条入口的动作与落点逐字相同、版本号与版本不匹配。
  ⚠️ 其中**五条 subtest 是本轮两轴审查后才补的**（原先没有）：
  ① 缝不接的 5 个动作种类（`type` / `key` / `inspect` / `execute_code` / `ask_user`）
  **必须报明确错误码，不许崩**；② 截图 / 等待**不要 target**；
  ③ **每条响应同一形状**（含 404）；④ 404 的响应体也带协议错误码。
  全部用**假桌面**（假截图源 / 假控件树 / 假注入器）：**不碰真桌面、不花钱**。
