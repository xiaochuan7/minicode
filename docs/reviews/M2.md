## 3. 与工单假设不符的现实

1. **冻结原型的 UIA 元素不暴露敏感属性** —— 脱敏器的密码框规则依赖 `IsPassword`，
   但 `src/minicode/exec/uia.py` 的 `Element` 只给 `name` / `automation_id` / `class_name` /
   `rect` / `control_type` 等，**没有 `Value` / `IsPassword` / `HelpText`**。
   → 真机 UIA 通道（M3）必须自己读 COM 属性，否则密码框规则在真机上永远不触发。
   本轮按「冻结原型不可改」的硬规则，**没有动 `exec/`**，只把这条缺口写进
   `docs/00-现状.md` §6.3 与 `docs/01-现状.md` §4 第 5 条。
2. **控件名与控件框在追踪记录/动作记录里保持原值** —— 脱敏只改「要外发的表示」。
   值不落记录（密码框留占位符，其余为空），但**控件名里如果恰好有密钥明文，仍会进日志**。
   落盘前的日志清洗是 M17 的活（本轮不做，也没假装做了）。
3. **正文类控件按类型子串判定**（`edit` / `document` / `text`），不是查枚举表 ——
   真机上的类型名可能带厂商后缀（`RichEdit` / `Document2`），子串判定更保守（宁可多丢）。
4. **工单的「配置层」在本轮之前没有对应的仓库配置项** —— 仓库唯一配置源是
   `src/minicode/model/config.py` 装载的 `.env`；本轮补了两个**可选**键
   （缺省都是关，fail-closed），非法组合在装载时就报错。
