## 0. 一句话结论

**危险动作审批上线了**：十一类危险动作**每类在执行前都产生审批请求**，请求绑定
**「意图 + 目标」**并带 **dry-run 的对象**（控件框 / 位置 / 截图哈希），结论绑定
**这一次动作**（拿上一次的结论来批这一次的动作不认）；**没批就零动作下发**，
任务停下来交给人。**闸门永远在**（fail-closed）：没接审批人 = 危险动作一律没批。

三件事值得单独说：

1. **闸门在四个下发点上**（一处实现，四个调用点）：动作执行缝（点击 / 截图）、
   动作执行器（**读剪贴板** / 提权弹窗）、决策层接口面（**不走缝**的输入文本 / 按键）、
   以及**抓帧之前**（敏感窗口的画面一旦进了模型上下文，审批就晚了）。
2. **「读剪贴板」只有一个读点**（粘贴通道的备份读）→ 没批就**不读**，
   改走 **Unicode 注入通道**（压根不碰剪贴板），退化**记一笔**。
3. **本轮改了 M10 的一处合同**（动作程序的行数预算只数程序自己的行）——
   不是本票要求的，但**不改就跑不通**（详见 §4.1）。

## 2. 设计

### 2.1 一处实现，四个调用点

| 调用点 | 问什么 | 问的时机 | 判据在哪 |
|---|---|---|---|
| `action/seam.py:530` | 这个**动作**危不危险 | 定位之后、**置前之前** | `approval/gate.py:133` |
| `action/seam.py:326` / `:744` / `:842` | 这一帧**能不能拍**（敏感窗口） | **抓帧之前**（定位那一帧 / 放大的回源重抓 / 截图动作） | `approval/gate.py:204`（`check_capture`） |
| `action/executor.py:365` | 「读剪贴板」 | 读之前 | 同上 |
| `action/executor.py:199` | 「提权弹窗」 | 检测到提权时 | 同上 |
| `decision/api.py:322` | **不走缝**的输入文本 / 按键 | 下发之前 | 同上 |

**为什么分四处**：这四件事在**动作的目标描述里看不出来**（目标名里没有「剪贴板」，
也没有「提权」）—— 判据必须问在**它真正发生的地方**。
⚠️ 但**闸门是同一个对象**（`action/seam.py:258` → `action/seam.py:269` 把同一个闸门
交给执行器）——「谁被问过」只有一份流水。

### 2.2 「没批就零动作下发」的三种落法

| 情形 | 落法 |
|---|---|
| 危险动作没批 | 缝返回失败（`approval_denied`）→ **一个输入都没发出去** → 决策层**停下来交人** |
| 读剪贴板没批 | **不读** → 改走 Unicode 注入通道（**文本照样输进去**，但**不碰用户的剪贴板**）→ 退化**记一笔** |
| 提权 | **零动作下发** + 「已交接给人」—— ⚠️ 提权这一类**批了也没用**（安全桌面上的输入到不了目标程序，C-07），所以审批请求**只作留痕** |

### 2.3 分类：关键词命中即生效（fail-closed）

* **中英文都收**：模型有时写英文意图（"click the Delete button"）——
  只收中文就等于**放行英文的同类动作**（那是静默执行）。
* **顺序即优先级**：「改注册表」排在「注册」前面（「注册表」里含「注册」）。
* **M12 的不可逆词表是本表的子集**（单测钉住）→ 两处判据不会各说各话。

### 2.4 闸门永远在（fail-closed）

`approval_gate or ApprovalGate()`：**没接就退到一个没有审批人的闸门** ——
危险动作一律没批，普通动作不受影响。
「不装闸门」**不是**一种放行配置（这是两轴审查抓出来的，见 §8.1 S12）。

## 4. 与工单假设不符的现实（9 条）

1. **本轮改了 M10 的一处合同**（动作程序的行数预算）—— 工单没要求，但**不改跑不通**：
   受控执行环境的行数上限原本**连框架的行一起数**，于是「多走一遍审批」就把
   同一段程序顶到了上限（端到端第一次跑时直接报 `program_rejected`）。
   改成**只数程序自己的行**（`action/program.py:323` 的 `_LineCounter` +
   `action/program.py:62` 的 `_PROGRAM_FILENAME`）：那个上限的本意是
   「**模型写的那段程序**的死循环兜底」，不是「框架这一轮干了多少活」的预算。
   ⚠️ 不改的话就是**静默失败**：同样的输入可能这次过、下次不过，模型背不了这个锅。
   → 口径写进 `docs/tickets/README.md`（「动作程序的行数预算只数程序自己的行」）。
2. **「读剪贴板」在本项目只有一个读点**（粘贴通道的备份读）—— 工单没说是哪一处。
   本轮的口径：**读剪贴板内容这件事本身要审批**；没批就**不读**，改走 Unicode 注入通道。
   ⚠️ 副作用：**每次输入文本都会问一次**（没批就退到 Unicode 通道，文本照样进去）。
   详见 §5 ①。
3. **工单 AC 1 把「读剪贴板」与 M20 的 AC 2 重复** —— `docs/tickets/README.md` 写死
   「M20 管『哪些窗口根本不许拍 / 不许发』（发送前的黑名单 + 剪贴板读取审批）」，
   而 M16 的 AC 1/AC 6 也点了它。本轮按**边界**拆开：**M16 给机制**（闸门 + 请求 +
   结论 + dry-run），**M20 给策略**（敏感窗口黑名单 + 策略成文）→ §5 ②。
4. **敏感窗口的判据缺一块**（Spec 审查 (c)3）：主路径上**抓帧**发生在审批之前 ——
   敏感窗口的画面会先进模型上下文，那时要紧的**不是**动作，是**画面**。
   → 已修：抓帧之前先问一次（`action/seam.py:326`）。
   ⚠️ 但**判据本身**（哪些窗口算敏感）归 M20，本轮**不自带词表** → 这一问在
   M20 接进策略之前是**空的**。
5. **审批之前桌面已经被动过**（Spec 审查 (c)4）：缝原来在审批之前就**置前**
   （把目标窗口顶到前面）。置前不注入任何输入，但它**改了桌面状态**。
   → 已修：审批挪到**置前之前**（`action/seam.py:530` 现在在置前块之前）。
6. **输入文本 / 按键这类动作**没有**定位目标** → dry-run 拿不到控件框与落点
   （那里根本没有控件）：只给**截图哈希**（`decision/api.py:330`）。
   ⚠️ 而且**输入的正文不进审批请求**（C-15：用户输入的正文不进日志，审批请求会落进
   动作记录）→ 正文只交给**分类**（判「这是不是一条命令」），单测
   `approval/test_approval.py:585`。→ §5 ③。
7. **M12 的 `DangerGate` 被本轮取代**（生产路径上不再有调用方）——
   **不删**（删它会让 `docs/reviews/M12.md` 里那份「文件:行号」证据全部悬空），
   但**新代码不要再接它**（写在 `approval/catalog.py` 的模块说明里）→ §5 ④。
8. **两个真机入口的差别**：`browser/__main__.py` 用的是**假注入器**（不发任何输入），
   不需要闸门；`uia/__main__.py` 与 `uia/live.py` 是**真机活体测试** → 装了闸门
   （`console_gate()`）—— 真机点「删除」现在会**先问人**。
9. **M14/M15 的端到端评测台没接闸门** —— 它的任务是**人工编排**的，危险任务本来
   标着「人工代确认」（`docs/target-tasks.md` §6）；接上闸门会把那些已验收的任务判失败。
   → §5 ⑤。

## 5. 需要人拍板的事（8 条）

1. **「读剪贴板」的口径**（§4.2）：本轮把**粘贴通道的备份读**也算成「读剪贴板」，
   于是**每次输入文本都要问一次**（没批 → 退到 Unicode 通道）。
   备选：① 备份读不算「读剪贴板」（它读完原地写回，**从不进模型**）→ 输入文本不需要审批；
   ② 算（现在的做法）；③ 给「备份读」单开一个更松的口径。
2. **敏感窗口策略归 M20**（§4.3）：本轮**不自带词表**，所以「截含敏感窗口的屏」
   这一类在 M20 接进策略之前**是空的**。要不要 M16 先垫一份保守词表？
3. **输入文本的 dry-run 拿不到目标**（§4.6）：要不要给「当前窗口标题 + 焦点控件」
   （需要 UIA 的焦点信息）？
4. **M12 的 `DangerGate` 要不要删**（§4.7）：现在它只被 M12 自己的单测用着。
5. **评测台要不要接闸门**（§4.9）：M14/M15 的端到端评测台现在**不接**闸门。
6. **十一类的关键词表**：本轮的词是**工单点名的十一类 + 同义说法**（中英文），
   **工程阈值·未验证**（没有语料统计过误报率）。要不要按真实任务日志校一遍？
7. **审批的粒度**：现在是**一次动作一次审批**（结论绑这一次动作）。
   要不要支持「本次任务内同类动作一次批准」？⚠️ 那与工单 AC 2「不是一次性授权
   后续同类动作」**互斥** —— 本轮按工单做。
8. **提权那一类的审批请求只作留痕**（§2.2）：批了也没用（安全桌面到不了目标程序）。
   要不要把它从「审批请求」里拿出来单列一类？
