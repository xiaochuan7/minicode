## 0. 一句话结论

**第二波的九张票建起来了，真机跑完：通过 4（WX-3 / E-1 / E-2 / E-3）／失败 2（CC-1、CC-2）／跳过 1（WX-1）／待人工确认 2（WX-2、CC-3），自动通过率 67%（4/6）。**

1. **WX-3 真过了** —— 评测台在微信窗口上造了一个**真模态**（宿主窗口因此被禁用），
   agent 检测到它之后**一个动作都没下发**，交出了**交接产物**（当前窗口标题 / 最后一步动作 /

3. **本轮让微信客户端回到了登录界面** —— 见 §6「本轮造成的影响」：这是我的操作造成的，
   需要人在手机上确认一次登录才能继续。

## 2. 设计

### 2.1 三个执行器，一份公共底座

| 模块 | 职责 |
|---|---|
| `e2e/apps.py` 的 `NativeAppExecutor` | **原生窗口应用**的公共底座（窗口锚定、能力表、缝的接线、真值、停止条件、交接产物、**置前纪律**） |
| `e2e/apps.py` 的 `WeChatExecutor` | 微信：**门控读数** + **模态弹窗**（检测 → 零动作 → 交人）+ 从 `automation_id` 挑联系人 |
| `e2e/apps.py` 的 `CcSwitchExecutor` | cc-switch：**UIA 通道可用** + 「当前配置」从**应用自己的状态库**读 + **配置还原** |
| `e2e/apps.py` 的 `ElectronExecutor` | DSH/Tabbit：**浏览器通道** + **输入通道退化** + 浏览器自己的输入通道 |
| `e2e/apps.py` 的 `CrossAppExecutor` | CC-3 那种**一张票跨两个应用**的（按步分派，上下文合在一起） |
| `e2e/modal.py` | **模态弹窗的检测**（纯函数 + Win32 读数） |
| `e2e/visual.py` | **视觉通道的接线**（M14 与 M15 **共用这一处**） |

### 2.2 结构断言的四种形态

M14 只有一种（`Expectation`：文本出现 / 消失 / 状态变化）。第二波逼出了另外三种 ——
**都是读应用自己说的状态**，不是看画面变了没有：

| 形态 | 为什么需要它 | 判在哪 |
|---|---|---|
| `expect_window_title` | 本机微信 4.1.15 的**聊天内容根本不在可访问性树里**（树只给外壳：导航、会话列表、标题栏） | 执行器读窗口标题（`apps.py` 的 `_judge_extra`） |
| `expect_control_value` | 本机微信的搜索框：**值**变了（输入了联系人名）而**名字**没变 | UIA 的 Value 属性 |
| `expect_context` | 本机 cc-switch 的**选中态在 UIA 里读不出来**（没有 Toggle / SelectionItem pattern） | 任务级读数（cc-switch 取**应用自己的状态库** `providers.is_current`） |

不变量随之放宽成「**每一步至少有一条结构断言**」（`e2e/tasks.py:95`）——
**仍然不许**只靠「画面变了」当通过判据。

### 2.3 「按停止条件结束的一步」不算失败

WX-3 那种一步**没有动作下发**、**期望没被判**（它压根没往下走）——
如果按普通失败算，**那张票明明做对了却判失败**。因此
`StepOutcome` 多了一个 `stopped` 字段（`e2e/runner.py:98`），
判定时**跳过**这类步（`e2e/runner.py` 的 `_verdict`）。

### 2.4 置前纪律：坐标不许挪到别的窗口

本机实测：**桌面注入只发给前台窗口的焦点控件**，而且 **SendInput 的返回值不说明
有没有送到**；窗口没在前台时，文字会落到**别的窗口**去（本轮探测就误打进过用户
记事本）。因此三个执行器都**先置前、再核对**（`apps.py` 的 `_focus_window` /
`_focus_browser`），置前不成功就**拒绝注入**（错误码 `target_window_not_foreground`），
并且**本机 `SetForegroundWindow` 会被系统拒绝** → 补了**ALT 技巧**（`apps.py:111`）。

## 4. 与工单假设不符的现实（8 条）

1. **本机微信的窗口标题不随联系人变** —— 工单 AC 写「进入聊天后窗口标题 == 联系人名」，
   实测（微信 4.1.15）：进入聊天后标题**仍是「微信」**，联系人名只出现在**聊天区标题**
   （而聊天区**不在可访问性树里**）→ 这条 AC 在本机**不成立**（如实记，不假装）。
2. **本机微信 4.1.15 的聊天内容根本不在可访问性树里** —— 树只给外壳：导航按钮、
   会话列表、标题栏；**聊天区、会话输入框、搜索结果都没有**（`Text` 类元素 0 个）。
   → 微信这一波只能验「树里有的东西」（搜索框的值、窗口标题、弹窗）。
3. **微信的会话条目名字是多行大 blob** —— `name` 里塞着聊天摘要与时间，
   干净的人名只在 `automation_id = session_item_<人名>` 里；
   **裸名字查询必然 0 命中**，而且 `unmatched` 也是 0 → 会被误判成「覆盖失败」
   （可切视觉）—— 这是 M9 那条口径（「名称匹配不上」≠「目标不在树里」）的一个**反例**。
   → 定位走「名字 + 控件类型」，挑联系人走 `automation_id`。
4. **cc-switch 停在设置页 → 供应商条目根本不在树里** —— 应用是 Tauri + WebView2，
   树是**完整的**（`usable`，50 个可用交互控件、无同名撞车），但**供应商列表只在
   供应商页上**；本轮它停在设置页 → 条目不在树里 → 覆盖失败 → 切视觉 →
   **标定没过** → 零动作下发。
5. **cc-switch 的「当前配置」在 UIA 里读不出来** —— 单选/开关的选中态只体现在
   class_name 里的 `bg-blue-500 text-white`（弱信号，且 Tailwind 变体源码会造成假阳性）；
   开关**只有 ValuePattern**（CurrentValue 是空），**没有 Toggle / SelectionItem**。
   → 「当前配置」的真值取**应用自己的状态库** `providers.is_current`（只读）。
6. **本机 cc-switch 的应用窗口标题是「CC Switch」** —— 工单与 `target-tasks.md` 写的
   `com.ccswitch.desktop-siw` 是那个 **22×22 的托盘辅助窗**（树里 0 个节点）；
   真正的应用窗标题是「CC Switch」（类名 `Tauri Window`），且**要先置前**树才完整。
7. **DSH Web GUI 需要本机鉴权令牌** —— 明文 URL 是 **401**
   （`dsh web authentication required`）；令牌在 harness 自己的凭据库里。
   → 本轮**没有**驱动 DSH 那个应用：E-1/E-2/E-3 跑在**评测台自带的本地验证页**上
   （同样是 Chromium/Electron 形态：扁平 DOM、页面结构定位、浏览器自己的输入通道）。
   ⚠️ 这一条**削弱了 E-1/E-3 的代表性**（见 §5 ④）。
8. **标定是抽签** —— 同一张探针、同一模型，四次跑分别是 **1.06 / 2.66 / 68.00 / 68.81 px**
   的最大误差（都要 > 1.0 px 容差）→ **本轮每一次切视觉都被准入门拦下**。
   M8/M9/M14 已记过同一条（抽签）；**这条是 cc-switch 两张票失败的直接原因**。

## 6. 本轮留下的欠账 + 本轮造成的影响

**本轮造成的影响（如实记）**：

* **微信客户端回到了登录界面** —— 为了让 UIA 通道有一棵可读的树，本轮**重启了微信客户端**
  （重启前它的树在一次探测后塌成了 1 个元素且**解不开**）。重启后客户端要**在手机上
  确认登录**才能继续 → **需要人做一次手机确认**（属人工代确认，本轮不代劳）。
  恢复之后，WX-1 与 WX-2 可以在同一套工单上重跑。
* **早前一次探测把「云老师云老师」误打进用户记事本未保存的缓冲区** → 已删回原样
  （截图核对过：「Version 2.1, February 1999」那行已复原；**磁盘文件始终没动**）。

**欠账**：

* **WX-1/WX-2 还没在真机上跑过**（等微信登录回来）。
* **CC-1~CC-3 还没跑通**（供应商条目不在树里 + 标定闸门）。
* **E-1/E-3 的代表性受限**（跑在本地验证页上，不是 DSH Web GUI）。
* **「判不了」这一档**（M14 的待拍板 ⑤）在本轮又出现了一次：WX-3 那一步的期望
  **判不了**（它压根没往下走）—— 本轮用 `stopped` 把它从失败里摘出来，
  但「判不了要不要单开一档」那条仍然挂着。
* **`e2e/apps.py` 已经 1500+ 行** —— 三种应用形态的公共部分在 `NativeAppExecutor`，
  但浏览器那一路与原生那一路仍有共用的「置前 / 坐标换算 / 真值」逻辑；
  再加第三种形态之前应该先抽。
