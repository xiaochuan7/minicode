## 0. 一句话结论

**在留出集 B 上，门控开 47.6% vs 门控关 47.6%，差 +0.0 pp ≤ 噪声量级 14.3 pp
→ 判「不成立」。** M8 的 +2.4 pp 全部落在噪声带内，且它只来自 1 条样本。

**A（调参半）上的 +4.8 pp 只是调参过程量** —— 那 1 条翻转**完全归因于模型调用失败**
（门控可归因 0 条）。**门控唯一的确定收益是省模型调用**（B 上门控关闭率 19.0%）。

## 3. 与工单假设不符的现实（4 条）

1. **`model-requests.jsonl` 里没有 prompt / 回答正文**（只有 effort / latency / token 数）
   → 「应答记忆端口」**无法从它重放**。本单的留出集重评建在 `sspro-report.json` 的
   **逐样本 outcome** 上（记录里有 coarse_point / landing_point / gate_reasons / hit）——
   这够用，但**不是**一次真模型重跑。**已开 M35**（让应答记忆端口可重放）。
2. **一致性距离与偏离距离都没被记录** → 换容差时部分样本「判不了」。
   处理：**给区间（悲观下界），不编点估计**，并用**重放自检 42/42** 当护栏。
3. **工单原文把 M8 的证据读串了**（已按 2026-10-21 口径更正工单 L12）：
   「35/42 条两臂粗定位点不同、11 条命中翻转」是**应答记忆端口之前**那一轮的数
   （M8.md §3.1 自己标了「第一轮的数作废、不引用」）；**端口之后实际只差 6/42**。
   本单实测的噪声面就是 **6/42 = 14.3%（B 上 3/21）**。
4. **M8 的 `runs/bench*/grounding-bench.json` 不是 M8 的产物** —— 那是 `minicode.ground`
   测量台（M6/M9）的产物。M8 真正的产物是 `runs/m8/`（门控自带 128 px）与
   `runs/m8-t16/`（调到 16 px），各含 `sspro-report.json` + `model-requests.jsonl`。
   本单的输入是 **`runs/m8-t16/sspro-report.json`**。
