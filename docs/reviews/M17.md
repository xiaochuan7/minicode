## 0. 一句话结论

**动作日志能回放了**：从日志**重建**每一步的动作，再用**独立判据**核对
（重建结果与当时的记录一致）；日志能导出成**机器可读**的 JSON，**成功率、
三类失败分布、三段耗时分布**都能从导出文件里算出来（不依赖人工看）；落盘前
用**脱敏器同一套规则**脱敏，日志里不再有密钥形态的明文，而**截图哈希没被误伤**。

三件事值得单独说：

1. **脱敏点选在 `ActionRecord.to_dict()`** —— 它是**所有**落盘路径（动作日志 /
   决策层的 `action-records.json` / 命令行打印）的唯一出口，一处脱敏覆盖三条路。
2. **回放不是把字段再读一遍**：动作是从日志**重建**成 `Action` 对象的
   （`reconstruct_action`），再用**独立判据**核对（结果自洽 / 三类失败归类 /
   失败类型 ↔ 错误码 / 时间顺序 / 三段耗时占比 / 落点落在目标控件框内）。
3. **两轴审查抓出了三处真问题**（§8）：**两个包互相依赖**（已把脱敏规则搬回
   下层的脱敏器包）、**「三类失败分布」里决策失败恒为 0**（决策失败不在动作
   记录里，已改成从决策层的遥测并进来）、**导出不清洗**（已补）。

## 2. 设计

### 2.1 三处：脱敏 / 回放 / 导出

```
动作记录（内存）  ──to_dict()──▶  脱敏（脱敏器同一套规则）──▶  落盘形状（JSON）
                                        │
                                        ├──▶ 动作日志（JSONL）──▶ 回放 ──▶ 回放报告
                                        │                     └─▶ 导出（JSON）─▶ 离线统计
                                        └──▶ 决策层的 action-records.json（数组）
```

* **脱敏**（`minicode/redact/log.py`）：只做一件事 —— 把密钥形态的明文从**落盘形状**里
  抹掉。**摘要字段按键名 + 值一起认**（`sha256` 结尾**且**值是 64 位十六进制）。
  ⚠️ **它住在脱敏器包里，不在审计包里**（理由见 §8.1 S4）。
* **回放**（`minicode/audit/replay.py`）：**重建动作 + 独立不变量核对**。
  **不碰桌面、不调模型**。
* **导出**（`minicode/audit/export.py`）：一个 JSON 文件，`records` + `summary`。
  分位数与中位数的算法复用 `minicode/ground/stats.py` 那一份（**不另写**）。

### 2.2 「字段完整」的判据（按动作种类）

| 字段 | 什么时候必须有值 |
|---|---|
| 时间 / 动作类型 / 结果.ok / 结果.error_code | **一直**（失败必须有码） |
| 落点坐标 + 空间 | 需要落点的动作种类（`POINT_KINDS` + 观察型的 `zoom`）**必须**有，空间必须是 `physical-surface`；不需要落点的动作种类（`screenshot` / `wait`）**必须没有** |
| 截图哈希 | 这一步抓过帧就**必须**有（64 位十六进制） |
| 目标窗口句柄 + 标题 | 选中过目标就**必须**有 |
| 动作前后状态 | 跑过校验（记录里有 `verification_result`）就**必须**有 |
| 动作类型 | **动作下发过**就必须有；**定位阶段就失败的步骤没有下发动作 → 没有动作类型是如实的**（§4.1） |

### 2.3 回放核对的判据（各自独立重算）

| 判据 | 拿什么跟什么比 |
|---|---|
| 结果自洽 | `ok` 与 `error_code`（成功不带码 / 失败必带码 / 码在协议里） |
| 三类失败归类 | 失败的步骤**恰好一个**失败字段非空，且它的值 == 错误码 |
| 失败类型 ↔ 错误码 | 用 `action/errors.py` 那张**唯一**的映射重算（只在定位阶段失败时对齐 —— 失败类型是**定位阶段**那一维的分类） |
| 时间顺序 | 时间戳不倒退（步骤顺序不能乱） |
| 三段耗时占比 | 占比必须等于由那三个值算出来的值（占比是**算出来的**，不是另一份数据） |
| 落点 ⊆ 控件框 | 落点必须落在**记录里的**目标控件框内（两个都是日志里的字段） |
| 回放（可选） | 把重建出来的 `Action` 再执行一遍，结果与记录不一致就点名 |

**「不依赖人工看」的证明**：下面这段**纯标准库**脚本（**不 import 本项目任何一个模块**）
读导出文件就把三样统计算出来了 —— 与 `summary` 里的数一致：

```python
import json, statistics
from pathlib import Path
payload = json.loads(Path('runs/m17/action-log-export.json').read_text(encoding='utf-8'))
records = payload['records']
ok = sum(1 for r in records if r['result']['ok'])
print('步数 =', len(records), '成功 =', ok, '成功率 =', ok / len(records))
dist = {}
for r in records:
    for name, code in r['failures'].items():
        if code:
            dist[name] = dist.get(name, 0) + 1
print('三类失败分布 =', dist)
for stage in ('locate', 'decision', 'execute_verify'):
    vals = sorted(r['timings_ms'][stage] for r in records)
    print(f'{stage}: 中位数={statistics.median(vals)} 最大={vals[-1]}')
```

## 4. 与工单假设不符的现实（10 条）

1. **定位阶段就失败的记录里没有动作类型** —— 工单 AC1 写「每条记录含……动作类型」，
   但**定位失败时动作压根没构造出来**（`action/seam.py` 的失败路径不造 `Action`），
   那种记录里 `action` 是空串。
   → 本轮的口径：**定位阶段就失败的步骤没有下发动作 → 没有动作类型是如实的**
   （`audit/replay.py:300`）；动作下发过却没有动作类型 = 缺字段。
   ⚠️ **要补「尝试过的动作」会动 M12 的重复动作检测器**（它的哈希里含动作种类，
   `reflection/stop.py:179`）→ §5 ①。
2. **M0 的老路径（`action/windows.py` 的控件树）不给窗口标题** —— AC1 点名
   「目标窗口句柄**与标题**」，而那条路径只给句柄（`action/windows.py:278`）。
   生产路径是 UIA 通道（M3+），它给标题（`uia/windows.py`，M11 加的）。
   → 本轮**没有**动真机路径（`GetWindowTextW` 在本机没法离线单测）→ §5 ②。
3. **落点复验失败的记录原先没有归进三类失败** —— `action/runner.py` 原来只改了
   `ok` / `error_code`，三类失败字段仍全空 → 这一步的失败**在日志里查不出来**，
   导出统计也会**漏掉它**。本轮补上（`action/runner.py:183`，归「执行失败」，与
   `action/errors.py` 的 `LANDING_MISMATCH → execution` 一致）。
4. **落盘形状有两种** —— 动作日志是 **JSONL**（`action/records.py` 的 `ActionLog`），
   决策层写的是 **JSON 数组**（`decision/__main__.py:248`）。离线工具两种都认
   （`audit/__main__.py:26`），但**没有统一** → §5 ③。
5. **脱敏点让「落盘形状」不再等于「内存里的记录」** —— `to_dict()` 现在会脱敏
   （`action/records.py:330`）。内存里仍保留原文，落盘上才是脱敏过的。
   → 口径已写进 `docs/tickets/README.md`。
6. **摘要字段不能只看键名** —— 截图哈希是 64 位十六进制，按脱敏器的
   「长十六进制串」那条规则会被**整条抹掉**（`redact/log.py:52`）。
   ⚠️ 这是**工单没提的坑**：照搬脱敏器的规则而不放行摘要字段，AC1 的
   「截图哈希」与 AC4 会直接互相打架；而**只按键名放行**又留下一个洞
   （明文藏在 `*_sha256` 字段里就查不出来了）→ **键名与值都得像摘要**。
7. **分位数与中位数的算法要复用 `ground/stats.py` 那一份** —— 审计层不另写一套
   （`audit/export.py:199`）。代价是审计层 import 了视觉通道的包（纯标准库，
   不引入第三方依赖）。
8. **工单没要求 CLI** —— 本轮加了 `audit/__main__.py`（离线统计与回放的入口）。
   理由：AC3 说「供自己离线统计与回放分析」，没有入口就只是库。
   ⚠️ **与 M18 的边界**：M18 的 CLI 是**对外的产品接口**（发起动作、读回结果），
   本单的命令行是**本地离线工具**（只读日志、只写导出文件）→ §5 ④。
9. **决策失败不在动作记录里** —— 动作记录只有「定位失败」与「执行失败」两处
   （`action/seam.py` 的三处失败路径都只设这两类；决策层那一步压根没进动作层），
   决策失败由**决策层单独报**（`verification/telemetry.py`）。→ 导出统计要把
   **遥测报告一起给进去**（`--telemetry`），否则那一类恒为 0
   （`audit/export.py:98`，来源写在 `failure_sources` 里）。
10. **输入文本的动作无法忠实回放** —— 那一步的正文**不进日志**（C-15：界面内容
    不进日志），所以重建出来的 `type` 动作没有正文。这是**有意为之**，不是漏了。

## 5. 需要人拍板的事（6 条）

1. **AC1 的「缺字段即不合格」是按字面还是按动作种类**（§4.1）：按字面读，
   **定位阶段就失败的步骤永远不合格**（它没有动作类型 / 落点 / 窗口句柄）；
   本轮按**不适用就不算缺**实现。备选：① 按字面收紧（那这类步骤要另设一档
   「未下发动作」）；② 就按现在这样，但把口径写进工单。
   ⚠️ 连带一条：定位失败的记录要不要补「**尝试过的动作**」？补了更完整，
   但会改 M12 的重复动作检测器的行为（连续几次同样的定位失败会被判成
   「重复动作」）→ 要不要把那个哈希改成**只看下发了动作的步骤**？
2. **M0 老路径要不要补窗口标题**（§4.2）：补 = 读 `GetWindowTextW`（真机路径，
   本轮没动）；不补 = 那条路径上的记录缺标题（AC1 不达标）。
   备选：把 M0 老路径标成「不保证字段完整」，或者干脆**退役**它（生产路径是 UIA 通道）。
3. **两种落盘形状要不要统一**（§4.4）：动作日志 JSONL vs 决策层 JSON 数组。
   本单的工具两种都认；但「一种形状」对离线统计更友好。
4. **CLI 的边界**（§4.8）：本单的 `python -m minicode.audit` 与 M18 的对外 CLI
   是不是应该合成一个入口？（M18 会自己带一套 CLI。）
5. **「字段完整」里「窗口标题必须有值」这条是否太严**：假实现与老路径给不出标题时，
   要不要允许「标题为空但记一条说明」？
6. **导出格式要不要给一份 schema**（JSON Schema）：现在靠 `format` 字段认格式，
   没有机器可校验的结构定义；给别的工具用时它们得自己猜字段。
