## 3. 与工单假设不符的现实（九条）

完整版见 `docs/00-现状.md` §6.9。摘要：

1. **门控在生产接线上基本是「哑」的** —— 四条条件只有「粗定位为空或越界」可判定，
   另外三条在 17/17 个样本上**不可判定**（只给点不给框 / 模型不报置信度 /
   没做第二次独立粗定位）→ 门控开 = 只做粗定位。**要真正起作用，需要让粗定位
   额外报目标框（改 M6 口径 + 重测）—— 需要人拍板。**
2. **本机上「门控关」比「门控开」好**（同一轮内：粗定位中位数 25.20 px →
   精定位 12.50 px；p90 86.54 → 79.06 px），与 C-16 引用的 ScreenSpot-Pro 证据
   （整体 −0.3pp）**方向相反**。样本集与模型都不同，**M8 同表跑才是裁决点**。
3. **「偏离粗定位 → 回落」抓不住「粗定位本身就偏」的情形** —— 实测有一个目标
   粗定位偏 124.52 px、精定位偏 207.00 px（选中了相邻同类控件），两落点相距在
   阈值内 → 没回落。阈值 128 px 是**未验证**的工程值（测量台现在逐目标记
   `refine_deviation_px`，M8 可拿它调阈值）。
4. **AC 1 与 AC 3 在「粗定位为空/越界」上只有一种读法能同时成立**：整屏第二遍
   **成功**就落它的点，**失败**才报定位失败。本实现取这一读法；那一遍**不是逐字
   重发**（提示词带上失败原因），但**也不是重新感知**（同一帧）。
5. **ShowUI 的网格值 = 1000，不是 999**（实际脚本逐行核实）。
6. **ShowUI 的 GT bbox 也是宽高形式**（与 CCF 一样）。

9. **门控的置信度 / 一致性阈值当前没有可靠来源**（模型不报置信度、没做第二次粗定位），
   来源串写「工程阈值·未验证」。
