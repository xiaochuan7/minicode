# 决策层产出代码执行 harness，而不是逐条吐动作

决策层的产出形态定为**一段由模型编写、在受控环境里执行的动作程序**，而不是让模型一步一条地吐动作。理由：可核的证据是官方仓库 README 正文里的两组数——用同一批模型只换 harness，平均部分分 45.3→64.9、步数 −53%；而代码执行相对同等 GUI + 命令行权限还额外带来 +6.1 分、步数 −14.8%，说明收益来自"把循环与分支的控制权写进代码"，不是"多给一个 shell"。逐条吐动作会让每一步都付一次网络往返与一次推理，且循环与分支无法由中间结果驱动。

## Considered Options

- **逐条吐动作**：实现简单、每步可观测，但控制权仍在模型手里，与上述两组证据方向相反。

## Consequences

- 动作协议里出现「执行代码」这一类动作，决策层是它唯一的产出者。
- **引用纪律**：另有一组更宽的区间（+15.5~+33.6 分、步数 −55~63%）**不在该仓库 README 正文里**，属于禁止引用的一档——要用必须先回查论文消融表并标出表号。
