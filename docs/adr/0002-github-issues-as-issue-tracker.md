# 议题跟踪器选 GitHub Issues，而不是本地 markdown

工单与需求的落地位置定为 **GitHub Issues**，通过 `gh` 命令行操作。理由：仓库已建好并认证，`gh` 已就位，五个分诊标签已存在，且 GitHub 的原生子议题与依赖关系可用——阻塞关系因此能表达成平台上可见的关系，而不是正文里的一行字。

## Considered Options

- **本地 markdown**：纯离线可用，但没有阻塞语义、没有标签流转、也没有跨工具可见性；一旦联网还需要一次全量迁移。
- **GitLab 等其他平台**：能力与 GitHub 相当，但没有理由在已有仓库之外再开一个。

## Consequences

- 所有议题操作走 `gh`，且必须用全路径调用（本机 `gh` 不在 PATH 上）。
- 分诊角色固定为五个标签，词表由跟踪器配置记录。
