# 架构主线是「结构优先、视觉兜底」，不是「视觉优先」

minicode 的默认定位路径是**读控件可访问性树、在控件上操作**，视觉推理只在树覆盖不到时兜底。理由：控件树给出的包围盒是物理像素，零缩放换算、零漂移、零模型成本；官方论文的同表对照里纯可访问性树 12.24 最高、纯截图 5.26 最差，而「截图 + 树」12.17 反而优于纯截图的方案。同时树并非全覆盖——Apple 的人工标注显示大部分屏幕至少有一个可见元素在树里没有匹配——所以视觉通道必须存在，但它只能是**罕见兜底**。

## Considered Options

- **视觉优先**：单一技术栈、跨应用一致，但把坐标漂移与模型 grounding 误差放在每一步的关键路径上，且失败是静默的。

## Consequences

- 从 UIA 通道切到视觉通道**只允许因覆盖失败而发生**；候选不唯一、被遮挡、尺寸异常、查询超时、名称匹配不上都走错误处理，不切视觉。否则兜底会从罕见退化成每步都付 1.5~5 秒。
- 能力表按应用逐个探测，记录三态，不允许出现"某类应用一律可用/一律不可用"的类别级结论。
