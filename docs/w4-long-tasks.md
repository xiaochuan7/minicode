# W4 长任务评测集：10 条跨应用任务，带故障注入（设计文档）

> 2026-11-03 夜间定稿。执行器与判分实现：`scripts/w4_long_tasks.py`；
> 实测结果：`docs/w4-long-results.md`（跑完生成；没跑完的如实写「未跑」）。

## 一、设计口径

**与 W4 第一批（30 条短任务，`taskbench.py`）的关系**：第一批验证的是
「结构化通道 + 判分器可信」（s@1=99.6%），步骤粒度小、无故障。本批回答
两个新问题：

1. **长链路**：10~30 步、跨窗口/跨应用、中途要**保留状态**的任务，系统
   能不能端到端做对；
2. **自愈**（W5）：中途注入的故障（对话框 / 遮挡失焦 / 位置漂移 / 元素
   禁用）能不能被**自动救回来**，以及救回来 vs 一次做对要分得清。

**执行模型**：步骤是**声明式**的（与第一批同一执行通道：带护栏的
`ActionService`，UIA 优先、视觉兜底），但每步包一层**自愈包装**（W5 的
失败分类 → 策略 → 记录）。故障注入由 **harness** 做（不是被测系统），
每条任务 1~2 次，时机在步骤序列里声明。

**判分三件套**（每条）：

* `reset` —— 幂等恢复初始态（删产物 / 造输入文件 / 杀残留实例）；
* `judge` —— 只读**状态**（文件内容 / 窗口标题 / 控件值），含**终态断言**
  与**关键中间断言**（中间断言是「一次做对 vs 自愈救回」可分的前提）；
* `budget` —— 步数上限 + 墙钟超时（超时 = 该 attempt 失败，如实记）。

**指标**：

* `success@1` = pass / (pass + fail + error)，`blocked`（环境起不来）与
  `paused`（人让位）剔出分母；
* **自愈拆分**：pass 里再分 `clean`（一次做对：零自愈触发）与
  `healed`（至少一次故障被自愈策略救回）；fail/error 里区分
  `heal_exhausted`（自愈试过没救回）与 `no_trigger`（没触发自愈就死了）；
* 故障维度：每次注入的**类型 × 是否触发自愈 × 是否救回**。

**borrowed 形态声明**：任务形态借鉴 OSWorld / Windows Agent Arena 的公开
设计思路（跨应用、终态校验、环境重置三分结构）；**所有数字只来自本机
实测**，不引用任何外部分数。

## 二、故障注入器（harness 侧，四类）

| 代号 | 类型 | 实现方式（全部可确定性复现） |
|---|---|---|
| F1 | 中途弹出需关闭的对话框 | harness 用独立进程弹原生 `MessageBox`（标题「系统提示」，正文与任务无关）；agent 需识别为非任务窗口并关闭 |
| F2 | 目标被遮挡 / 窗口失焦 | harness spawn 第二个空白记事本置顶盖住当前活动窗的一部分，或激活无关窗口抢焦点 |
| F3 | 目标位置漂移 | harness 用 `SetWindowPos` 把任务窗口平移 +260/+340 px（不含负向，避免移出屏幕） |
| F4 | 元素暂时禁用（需等待或换路径） | 把目标文件设**只读**（保存必被拒，需另存新路径）或把一个输入文件**延迟 30s** 才落盘（需等待重试） |

注入时机：声明在步骤序列中间（`{"fault": "F1"}` 作为特殊步骤）。故障
窗口/状态由 harness 记录（`faults.jsonl`）：类型、注入时刻、agent 何时
恢复（下一步成功即视为恢复）。

## 三、任务集（10 条）

通用约定：所有产物只写 `runs/w4-long/tmp/`（任务前缀隔离）；输入文件由
reset 生成；「记事本」= notepad、「计算器」= calc、「浏览器」= Edge
（本地 file:// 页，自建）、「资源管理器」= explorer。

---

### T1 算术账本（calc → notepad）——F3 漂移 ×1

* **目标**：计算器连算 5 个表达式，每个结果记入记事本，落盘为账本文件。
* **步骤数**：~22（开 calc ×1、算 ×5（每位数输入+等号）、切窗 ×5、
  notepad 输入 ×5、保存 ×2、关窗 ×2…）。
* **状态链**：算式结果只在计算器显示屏上存在 → 必须先读数再切窗写入。
* **故障**：第 3 个算式完成后，calc 窗口被平移 +300px（F3）→ 下一步
  「在计算器上继续输入」必须重新定位。
* **reset**：删 `t1-ledger.txt`；杀 calc/notepad 残留。
* **judge**：终态 = `t1-ledger.txt` 恰 5 行且每行 `算式=结果` 与预置答案
  逐字一致；中间 = 第 3 行写入后文件已存在且恰 3 行。
* **budget**：30 步 / 20 分钟。

### T2 网页数据摘录（Edge → notepad）——F1 对话框 ×1

* **目标**：本地 HTML 数据页（6 项库存表）里读出指定 6 项的数值，抄进
  记事本另存。
* **步骤数**：~18（开 Edge ×1、读 ×6（UIA 读不了 canvas 内的值 → 本页用
  真文本 DOM，UIA 可读）、切窗、写入 ×2 批、另存、关闭）。
* **故障**：第二批抄写前弹「系统提示」MessageBox（F1）→ 需识别并关闭。
* **reset**：生成数据页 HTML；删 `t2-extract.txt`。
* **judge**：终态 = `t2-extract.txt` 含 6 个 `名称:数值` 行且数值正确；
  中间 = 前 3 项已在文件中。
* **budget**：28 步 / 18 分钟。

### T3 双文件汇总（notepad ×2 实例）——F2 遮挡 ×1

* **目标**：A.txt（3 个数）与 B.txt（3 个数）的 6 个数全加，结果写入
  C.txt。
* **步骤数**：~20（开 A → 抄 → 开 B → 抄 → 开 C → 输入 → 保存 → 校验）。
* **故障**：抄写中途，B 窗口被置顶并移动到盖住 C 的编辑区（F2）→ 需
  切换/最小化遮挡窗再继续。
* **reset**：生成 A/B（数值固定），删 C。
* **judge**：终态 = C.txt 内容 = 正确和（单行数字）；中间 = A、B 的值
  已在 C 的草稿里（分两次断言）。
* **budget**：28 步 / 18 分钟。

### T4 只读模板换路径（notepad + calc）——F4 只读 ×1

* **目标**：打开只读模板 `t4-units.txt`（含 5 个待填换算），用 calc 算出
  5 个换算值填进去，保存。
* **步骤数**：~24。
* **故障**：文件是只读的（F4）→ Ctrl+S 弹「拒绝访问」对话框 → 正确
  行为是换路径另存 `t4-units-out.txt`（对话框处理 + 换路径双重考核）。
* **reset**：生成只读模板；删输出文件。
* **judge**：终态 = `t4-units-out.txt` 存在且 5 个换算值正确；原模板
  未被破坏（内容不变）。
* **budget**：30 步 / 20 分钟。

### T5 汇率换算三连（Edge → calc → notepad）——F3 漂移 ×1 + F1 对话框 ×1

* **目标**：本地汇率页读 USD→CNY 汇率，calc 算 3 笔金额换算，记账到
  notepad 保存。
* **步骤数**：~26。
* **故障**：第 2 笔前 Edge 被平移（F3）；第 3 笔前弹对话框（F1）。
* **reset**：生成汇率页（汇率固定 7.25）；删账本。
* **judge**：终态 = 账本 3 行金额正确（允许 ±0.01 舍入差，口径事前定）；
  中间 = 第 1 笔已记账。
* **budget**：30 步 / 22 分钟。

### T6 行号排版（notepad 单应用多轮）——F2 失焦 ×1

* **目标**：把 `t6-article.txt`（10 行短文）在记事本里每行行首加
  `01.`~`10.` 序号，另存 `t6-numbered.txt`。
* **步骤数**：~22（10 行 × 行首定位+输入 + 另存）。
* **故障**：第 5 行后 harness 激活一个无关窗口抢走焦点（F2）→ 需切回。
* **reset**：生成 article；删输出。
* **judge**：终态 = 输出 10 行且第 i 行 = `0i.原文`；中间 = 前 5 行
  已有序号。
* **budget**：30 步 / 20 分钟。

### T7 小票合计（explorer + notepad + calc）——F4 延迟出现 ×1

* **目标**：`t7-receipts/` 下 4 张小票 txt（各一个金额）逐个读出，calc
  累加，合计写 `t7-total.txt`。
* **步骤数**：~24。
* **故障**：第 4 张小票**延迟 30s** 才由 harness 落盘（F4）→ 第 4 次打开
  会失败，正确行为是等待后重试（等待+变化检测的考核点）。
* **reset**：删目录重建（先只放 3 张）；删合计。
* **judge**：终态 = 合计 = 4 张之和；中间 = 前 3 张的和已正确（第 4 张
  到账前的中间断言）。
* **budget**：30 步 / 25 分钟。

### T8 跨窗文本搬运（notepad ×2）——F1 对话框 ×1 + F3 漂移 ×1

* **目标**：把 `t8-src.txt` 的内容全选复制到 `t8-dst.txt`，并在首行加
  `COPY:` 头、末行加 `END` 尾，保存。
* **步骤数**：~16。
* **故障**：复制前弹对话框（F1）；粘贴前 dst 窗口被平移（F3）。
* **reset**：生成 src；删 dst。
* **judge**：终态 = dst = `COPY:` + src 内容 + `END`；中间 = src 内容
  已进剪贴板不可判 → 用「dst 已打开且为空」做中间断言。
* **budget**：24 步 / 15 分钟。

### T9 延迟模板汇总（notepad + calc）——F4 延迟 ×1

* **目标**：`t9-input.txt`（harness 30s 后才写入，含 6 个数）出现后求和
  写 `t9-result.txt`。
* **步骤数**：~18（其中等待重试若干）。
* **故障**：输入文件延迟出现（F4）→ 打开失败需等待重试。
* **reset**：删输入与结果（reset 本身不生成输入——由故障注入器延迟生成）。
* **judge**：终态 = 结果 = 6 数之和；中间 = 无（等文件是第一关）。
* **budget**：24 步 / 25 分钟。

### T10 全链路订单（Edge → calc → notepad）——F1 + F2 + F3 各 ×1

* **目标**：本地购物车页（3 件商品单价）→ calc 求和 × 税率 1.08 →
  按模板 `t10-invoice-template.txt` 填成发票，另存 `t10-invoice.txt`。
* **步骤数**：~30（上限档）。
* **故障**：读价后弹对话框（F1）；填模板时无关窗抢焦点（F2）；保存前
  notepad 被平移（F3）。
* **reset**：生成购物车页与模板；删发票。
* **judge**：终态 = 发票 3 行单价 + 合计（含税，±0.01）+ 模板字段齐全；
  中间 = 合计已在 calc 显示屏（读控件值）。
* **budget**：34 步 / 25 分钟。

## 四、判分口径细则

* 数值断言：金额/换算允许 **±0.01** 舍入差（事前定死，不含糊）；整数
  断言必须逐字相等。
* 中间断言失败 = 该 attempt 记 `fail`（`breakpoint` 原因），即使终态
  后来是对的 —— 中间断言的意义就是把「侥幸做对」和「过程正确」分开。
* 故障恢复的正确性不单独给分：故障被处理且终态 pass → 计 `healed`；
  故障没被处理但任务仍然 pass（例如绕开了被遮挡区域）→ 也计 `healed`
  （标注 `bypassed`）。
* 每步的自愈记录（W5 的 jsonl）与本判分**互相独立**：判分只看状态。

## 五、风险与裁剪预案

* explorer（T7）的 UIA 树在真机上层次深、易超时：若 pilot 连续两轮不绿，
  按「卡住怎么办」条款把 T7 降级为「notepad 直接打开路径」（仍保留 F4
  延迟注入），并在报告里如实记录降级原因。
* 10 条全量真机跑不完 → 按任务书纪律保留已跑部分，未跑的写明。
